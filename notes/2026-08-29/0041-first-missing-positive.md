# 41. 缺失的第一个正数

状态：✅ 已解决（LeetCode 通过）

## 题目目标

在未排序整数数组 `nums` 中，找出没有出现的最小正整数。

要求：

- 时间复杂度 `O(n)`
- 只使用常数级额外空间
- 输入可能包含负数、0、重复数字和很大的正数

## 示例

```text
[1, 2, 0]       -> 3
[3, 4, -1, 1]   -> 2
[7, 8, 9, 11, 12] -> 1
```

## 学习结果

- 掌握通过下标归位把数组本身当作哈希表使用
- 理解答案一定在 `[1, n + 1]` 范围内，因此可以忽略负数、0 和大于 `n` 的数字
- 掌握重复数字的停止条件，以及 `&&` 短路求值对下标安全的作用
- 最终解答已在 LeetCode 通过

## 第一次提示：原地哈希 / 下标归位

长度为 `n` 的数组，其最小缺失正整数一定在 `[1, n + 1]` 中：如果 `1` 到 `n` 中有数缺失，答案就在其中；如果全部存在，答案就是 `n + 1`。所以负数、0 和大于 `n` 的数都不可能影响 `[1, n]` 中哪个数最先缺失。

利用数组下标建立对应关系：

```text
数字 1 应放在下标 0
数字 2 应放在下标 1
...
数字 x 应放在下标 x - 1
```

遍历每个位置时，只要当前数字 `x` 在 `[1, n]` 中且目标位置还不是 `x`，就把它交换到 `nums[x - 1]`。交换后当前位置出现了新数字，因此要继续检查当前位置，使用 `while` 而不是只判断一次的 `if`。

核心条件：

```cpp
while (nums[i] >= 1 &&
       nums[i] <= n &&
       nums[nums[i] - 1] != nums[i]) {
    swap(nums[i], nums[nums[i] - 1]);
}
```

最后再次从左到右扫描：第一个满足 `nums[i] != i + 1` 的位置，答案就是 `i + 1`；若全部匹配，答案为 `n + 1`。

第三个条件 `nums[nums[i] - 1] != nums[i]` 用于处理重复数字。例如两个 `1` 中已有一个位于下标 0 时，不应继续交换另一个 `1`，否则可能原地反复交换。

虽然代码中有嵌套 `while`，但每次有效交换都会让至少一个 `[1, n]` 范围内的数字到达正确位置，成功归位的次数最多是 `n`，因此总时间复杂度仍为 `O(n)`，额外空间为 `O(1)`。

## 最终解答

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        int n = static_cast<int>(nums.size());

        for (int i = 0; i < n; i++) {
            while (nums[i] >= 1 &&
                   nums[i] <= n &&
                   nums[i] != nums[nums[i] - 1]) {
                int x = nums[i];
                swap(nums[i], nums[x - 1]);
            }
        }

        for (int i = 0; i < n; i++) {
            if (nums[i] != i + 1) {
                return i + 1;
            }
        }

        return n + 1;
    }
};
```

最终检查：范围判断必须放在 `nums[nums[i] - 1]` 前面，否则 `0`、负数或大于 `n` 的数字会造成非法下标；目标位置已有相同数字时必须停止交换，否则重复数字会导致死循环。

## 用户实现 review

当前实现：

```cpp
int x = nums[i];
while (x != i + 1 && x >= 1 && x <= n) {
    swap(nums[i], nums[x - 1]);
}
```

有两个问题：

1. `x` 在 `while` 外只读取一次。第一次交换后 `nums[i]` 可能已经变成了另一个数字，但 `x` 仍是旧值，下一轮会继续交换旧目标，甚至把数组恢复原状并死循环。例如 `[3, 4, -1, 1]` 在 `i = 0` 时会在两个状态之间反复交换
2. 即使把 `x` 放到循环内，只判断 `x != i + 1` 也无法处理重复数字。例如 `[1, 1]` 在 `i = 1` 时，第二个 `1` 不在正确下标，但目标下标 0 已经是 `1`，反复交换不会产生变化

推荐让每轮都读取最新的 `nums[i]`，并判断目标位置是否已经有相同数字：

```cpp
while (nums[i] >= 1 &&
       nums[i] <= n &&
       nums[nums[i] - 1] != nums[i]) {
    int x = nums[i];
    swap(nums[i], nums[x - 1]);
}
```

这里第三个条件既避免重复数字导致的无效交换，也保证每次交换都能推进归位过程。

## 超时原因

当前版本又改回了：

```cpp
while (nums[i] != i + 1 &&
       nums[i] >= 1 &&
       nums[i] <= n) {
    int x = nums[i];
    swap(nums[i], nums[x - 1]);
}
```

这会在重复数字上无限循环，因此 LeetCode 报超时，并不是算法的正常时间复杂度变成了 `O(n^2)`。

例如 `nums = [1, 1]`，处理 `i = 1` 时：

- `nums[1] == 1`，但 `i + 1 == 2`，所以第一项条件成立
- `1` 在 `[1, n]` 范围内
- 交换 `nums[1]` 和 `nums[0]` 后数组仍然是 `[1, 1]`
- 下一轮条件完全不变，继续交换相同的两个数字

必须加回目标位置的重复检查：

```cpp
while (nums[i] >= 1 &&
       nums[i] <= n &&
       nums[nums[i] - 1] != nums[i]) {
    int x = nums[i];
    swap(nums[i], nums[x - 1]);
}
```

`nums[nums[i] - 1] != nums[i]` 的含义是：只有目标位置还不是同一个数字时才交换。这样每次交换都会产生有效进展，整体时间复杂度才是 `O(n)`。

## 运行时错误：下标访问顺序错误

当前条件：

```cpp
while (nums[i] != nums[nums[i] - 1] &&
       nums[i] >= 1 &&
       nums[i] <= n) {
```

把 `nums[nums[i] - 1]` 放在范围检查前面是不安全的。例如 `nums[i] == 0` 时，会先访问 `nums[-1]`；如果 `nums[i] == -1`，会访问 `nums[-2]`；如果 `nums[i] == n + 1`，会访问 `nums[n]`。`vector::operator[]` 不做边界检查，负下标还会转换成很大的无符号下标，因此 UBSan 会报告 unsigned offset overflow。

C++ 中 `&&` 从左到右求值，并且左侧为 `false` 时不会继续求值右侧。因此必须先检查范围，再访问计算出来的下标：

```cpp
while (nums[i] >= 1 &&
       nums[i] <= n &&
       nums[i] != nums[nums[i] - 1]) {
    int x = nums[i];
    swap(nums[i], nums[x - 1]);
}
```

前两个条件确保 `nums[i] - 1` 一定是合法下标 `0` 到 `n - 1`，第三个条件才可以安全访问目标位置。
