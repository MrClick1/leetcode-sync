## 写代码前先学两个小操作

### 检查最低位

```cpp
unsigned int x = 5;         // 二进制 0101
unsigned int bit = x & 1u;  // 得到 1
```

1 只有最低位是 1，其他位都会被 & 清掉。因此：

```cpp
(x & 1u) == 0  // 偶数
(x & 1u) == 1  // 奇数
```

1u 表示 unsigned int 类型的整数 1。

### 检查第k位

仍以 x=5 为例，检查第 2 位：

```cpp
int k = 2;
unsigned int bitK = (x >> k) & 1u; // 得到 1
```

从右边开始编号，最低位是第 0 位。先把第 k 位移到最右边，再用 &1u 取出来。k 必须非负且小于提升后左操作数类型的位宽。

## 二进制与位编号

位运算针对整数的二进制位进行操作，每一位只能是 0 或 1。从右边开始编号，最低位是第 0 位，接下来是第 1、2、3 位。

```text
二进制： 1  1  0  1
位编号： 3  2  1  0
位权：   8  4  2  1

13 = 8 + 4 + 1
```

下面经常只写四位来帮助观察，不表示 C++ 整数类型只有四位。先用非负整数理解移位；涉及负数、符号位时，再检查类型和题目约束。

### 负数、符号位与补码

本轮因 231 的 -16 输入开始学习负数表示。以下按常见的补码表示解释，用 8 位演示；不能把示意位宽当成实际 int 位宽。[当前 C++ 工作草案](https://eel.is/c++draft/basic.fundamental)规定的有符号整数表示也是补码，不据此泛化所有旧语言版本或其他编码。

采用补码的有符号整数类型对正数、零、负数统一使用补码，正数的补码恰好与原码相同；不是“正数存原码、负数存补码”。普通 int 不会同时保存原码/反码/补码三份编码，写 int n=-16 时也无需手动转换。

#### 原码、反码、补码的计算规则

先确定总位数。以能够用 8 位原码表示的 +16 和 -16 为例：

| 数值 | 原码 | 反码 | 补码 |
|---|---|---|---|
| +16 | 00010000 | 00010000 | 00010000 |
| -16 | 10010000 | 11101111 | 11110000 |

正数的原码、反码、补码相同。负数按如下步骤手算：

1. 原码：最高位写 1 表示负号，其余位写绝对值的二进制。-16 是 1 加上 7 位的 0010000，即 10010000。
2. 反码：保持负数原码的符号位 1 不变，其余位逐位取反，0 变 1、1 变 0。10010000 得到 11101111。
3. 补码：在该负数的反码上加 1。11101111+00000001 得到 11110000。

```text
-16 的原码   1 | 0010000
-16 的反码   1 | 1101111   <- 符号位不变，其余位取反
-16 的补码   1 | 1110000   <- 反码加 1
```

竖线只为分开符号位，不属于位模式。二进制加法满 2 进 1，末尾 1111 加 1 得 10000，所以 11101111 加 1 会连续进位成为 11110000。原码的符号位真是单独的符号，其余位是绝对值；补码中不能再按这种方式解释数值。

上述“从负数原码出发，保留符号位、其他位取反”与前轮“从对应正数出发，所有位取反”没有矛盾：出发点不同。+16 的最高位 0 全部取反后变 1；-16 原码的最高位已经是 1，保留它即可。两条路线都得到 -16 的反码 11101111，再加 1 得到补码。

原码/反码/补码是编码规则，不是说任意 C++ 整数的“反码”都等于直接执行 ~x。手算应固定宽度；负数补码常用“反码加一”，但正数补码不加一。8 位补码最小值 -128 没有同宽度可表示的 +128，也没有同宽度原码/反码表示，属于额外边界，不盲目对最小负数取绝对值。

参考：[UCC 课程：负数的三种二进制表示](https://www.cs.ucc.ie/osullb/cs1101/labs/12b/)、[Cornell：补码取反加一](https://www.cs.cornell.edu/~tomf/notes/cps104/twoscomp.html)。本轮仅手工推演与定义核对，没有新增 C++ 编译验证。

在固定宽度的有符号补码中，最高位为 0 表示非负，最高位为 1 表示负数。重要区别：最高位不是单独加上的负号，剩余位也不是绝对值。不能只把正数的最高位改成 1 就得到其相反数。

在该位宽能够表示正负两个值的前提下，求 -16 的位模式可手算为“写出 +16，所有位取反，再加 1”：

```text
 +16       00010000
 全部取反   11101111
 再加 1     11110000  <- -16 的 8 位补码
```

这里的“全部取反”限于演示的 8 位。不要直接用 int 的 ~16 只观察低 8 位，就忽略实际计算类型的其余位。

理解符号位可以看每位的权重：最高位的权重是负的，后面各位仍是正的。

```text
位权： -128  64  32  16   8   4   2   1
-16 ：    1   1   1   1   0   0   0   0

-128 + 64 + 32 + 16 = -16
```

因此 10010000 按 8 位有符号补码解释是 -128+16=-112，不是 -16。同一位模式 11110000 若按 8 位无符号数解释，则是 128+64+32+16=240；位模式必须结合类型解释，不能说所有二进制最高位 1 都代表负数。

以本题常见的 32 位 int 为例，展开为：

```text
 +16  00000000 00000000 00000000 00010000
 -16  11111111 11111111 11111111 11110000
  -1  11111111 11111111 11111111 11111111
```

-1 的推导同样是 +1 的位模式取反再加 1，所以该位宽中的所有位都是 1。常见有符号算术右移在左侧补符号位；负数补 1，而不是补 0：

```text
-16  11110000
 -8  11111000
 -4  11111100
 -2  11111110
 -1  11111111
 -1  11111111  <- 再右移仍相同
```

这就是 while(m) 不会正常等到 m==0 的原因。这里限定算术右移行为，相关规则见 [C++ 工作草案：移位运算](https://eel.is/c++draft/expr.shift)。复习时先记三点：负数常用补码；取反加一要固定宽度；算术右移会扩展符号。

#### 负数的左移与右移

先观察固定 8 位补码的位移动，不把这幅示意直接当作任意 C++ 版本的表达式规则：

| 操作 | 位模式 | 按 8 位补码解释 |
|---|---|---|
| 原数 | 11110000 | -16 |
| 左移 1 位 | 11100000 | -32 |
| 算术右移 1 位 | 11111000 | -8 |

左移：所有位一起向左移动，最左边移出的位丢弃，右侧空位补 0。最高位也参与移动，不是将符号位固定、只移动其余位。本例结果在范围内，因此像乘以 2；超出固定宽度的可表示范围时，不能继续当作无限精度乘法。

算术右移：所有位向右移动，最右边移出的位丢弃，左侧补原来的符号位。负数的符号位是 1，所以左侧补 1；11110000 变为 11111000，仍是负数。右移时不先转成原码，直接处理补码位模式。

算术右移的结果按除以 2 的数学商向下取整。例如 -5 的 8 位补码 11111011，右移后为 11111101，即 -3；不能将负数右移理解为总是向 0 截断。此前 -1 右移保持 -1，也是同一规则。

C++ 代码必须注意语言版本：

- C++17：对有符号负数做左移是未定义行为；负数右移的结果由实现定义，常见实现使用上述算术右移。即使某次运行得到期望值，也不能据此认定负数左移合法。[C++17 草案 N4659](https://timsong-cpp.github.io/cppwp/n4659/expr.shift)
- C++20 起：左移按类型位宽的模运算规则定义，右移明确为算术右移、数学商向下取整。本例 int x=-16 时，x<<1 为 -32，x>>1 为 -8。[C++20 草案 N4861](https://timsong-cpp.github.io/cppwp/n4861/expr.shift)
- 移位次数必须非负且小于整数提升后的左操作数位宽；小整数类型可能先提升为 int。因此 8 位演示不代表对 int8_t 写移位表达式就一定按 8 位计算。

刷题时优先用非负数或无符号数处理完整位模式，需要数值乘法时不要为了简短而对负数使用未经确认的左移。本轮仅查阅规则并手工推演，没有新增 C++ 编译测试，也不运行未定义行为来“验证”标准。

## 基本运算符

用 a=5（二进制 0101）、b=3（二进制 0011）观察：

| 运算符 | 名称 | 对应位的规则或动作 | 示例 |
|---|---|---|---|
| `&` | 按位与 | 两位都是 1 才得 1 | `5 & 3` 得 1 |
| `\|` | 按位或 | 至少一位为 1 就得 1 | `5 \| 3` 得 7 |
| `^` | 按位异或 | 不同得 1，相同得 0 | `5 ^ 3` 得 6 |
| `~` | 按位取反 | 每一位的 0 和 1 翻转 | 作用于整个计算类型的位宽 |
| `<<` | 左移 | 向左移动指定的位数 | `5 << 1` 得 10 |
| `>>` | 右移 | 向右移动指定的位数 | `5 >> 1` 得 2 |

先看按位与和异或的差别：

```text
   0101        0101
&  0011     ^  0011
-------     -------
   0001        0110
```

复合赋值会把结果保存回变量。对于这里的简单变量：

```cpp
res ^= x;       // 等价于 res = res ^ x;
n >>= 1;       // 等价于 n = n >> 1;
n &= (n - 1);  // 等价于 n = n & (n - 1);
```

## 异或与成对抵消

### 关键性质

```text
a ^ a = 0
a ^ 0 = a
a ^ b = b ^ a
(a ^ b) ^ c = a ^ (b ^ c)
```

任意数与自己异或，各位都相同，所以结果是 0。与 0 异或时，各位保持原值。交换律和结合律让相同数字可以在证明中配对，不要求它们在数组里相邻，也不需要真的排序。

### 在136中使用

题目保证一个数字出现一次，其余数字各出现两次：

```text
4 ^ 1 ^ 2 ^ 1 ^ 2
= 4 ^ (1 ^ 1) ^ (2 ^ 2)
= 4
```

```cpp
int res = 0;
for (int num : nums) {
    res ^= num;
}
```

res 是已处理部分的累计异或，中途不一定已经是答案。初值用 0，因为它不会引入额外数字；成对的负数也能抵消。

只出现一次的数字可以用这种方法，是由题目出现次数的约束决定的，不是所有找不同数字的题目都能直接全部异或。例如 a^a^a=a，三个相同数字不会抵消为 0。

完整用户通过实现见 [136 二刷笔记](2026-10-04/0136-single-number.md)。169 摩尔投票是不同元素配对抵消，不是异或算法。

### 在461中标出不同位

异或的另一种用途是比较两个数：对应位相同得 0，不同得 1。因此 x^y 标出了哪些位不同，再统计其中 1 的数量，就得到汉明距离。

```text
  x = 1：0001
  y = 4：0100
  x ^ y：0101
```

异或结果的数值是 5，但不同位的数量是 2，不能直接返回 x^y。用户已自行实现清位计数并反馈通过：0101 -> 0100 -> 0000，清两次，所以距离为 2。x==y 时结果为 0，不进入循环，距离为 0。

这就是把 461 转换为此前 191 的计数问题：异或标出差异，清位统计差异。用户写法与官解方法三 Brian Kernighan 算法一致；官解另有内置位计数和逐位右移。详细代码及对照见 [461 题目笔记](2026-10-04/0461-hamming-distance.md)。本轮仅静态核对和手动模拟，没有新增编译测试。

## 取位与逐位检查

### 取最低位

1 的二进制只有最低位为 1，所以 n&1 只留下最低位，结果只能为 0 或 1：

```text
   1101
&  0001
-------
   0001
```

```cpp
int bit = n & 1;
```

对这里的非负整数，最低位为 0 表示偶数，为 1 表示奇数。

### 右移后检查下一位

非负整数右移一位，相当于整数除以 2。原来第 1 位来到第 0 位，就能再次用 &1 检查：

```text
1101 -> 0110 -> 0011 -> 0001 -> 0000
```

```cpp
int countOnesByShift(int n) {
    int res = 0;
    while (n > 0) {
        res += (n & 1);
        n >>= 1;
    }
    return res;
}
```

这是对非负整数通用的逐位检查写法。每轮检查一位，即使那一位是 0 也会被检查。n=13 时，最低位依次为 1、0、1、1，累加得到 3。

### 右移表达式不会修改原变量

```cpp
m >> 1;   // 计算右移结果，m 本身不变
m >>= 1;  // 将右移结果写回 m，等价于 m = m >> 1
```

用户在 191 中尝试先累加 m&1，再循环 31 次累加 (m>>1)&1。虽然 &1 已经能得到 0/1，但 m 没变，右移距离也始终是 1，因此每轮都检查原数的第 1 位，循环变量 i 没有参与取位。

例如 n=11=1011，循环前 m&1 得到 1；每轮 (m>>1)&1 都是 0101&0001=1，最后结果为 1+31=32，而正确答案是 3。

保留原结构的修正参考（本题使用 32 位 int，输入为正整数）：

```cpp
int hammingWeight(int n) {
    int res = 0;
    int m = n;
    res += (m & 1);
    for (int i = 1; i < 32; ++i) {
        m >>= 1;
        res += (m & 1);
    }
    return res;
}
```

这时 m 依次是 1011、0101、0010、0001、0000；每次右移后，下一位才来到最低位。

也可以保持 m 不变，让右移距离随 i 增加：

```cpp
res += (m & 1);
for (int i = 1; i < 32; ++i) {
    res += ((m >> i) & 1);
}
```

两种方式选一种：更新 m 时每次右移 1 位；固定 m 时按 i 右移。不要既累计修改 m，又按不断增大的 i 移位，否则会跳过某些位。复盘口诀：取位检查当前位，赋值移位推进到下一位。

### 取第k位

先右移，把目标位搬到最右边，再取最低位：

```cpp
unsigned int x = 13;
int k = 2;
unsigned int bit = (x >> k) & 1u; // 第 2 位为 1
```

k 从 0 开始，必须非负且小于提升后左操作数类型的位宽。1u 表示 unsigned int 类型的整数 1。

### 用掩码检查第i位

1<<i 把整数 1 移到第 i 位，形成只在这一位为 1 的掩码。与原数做按位与后，其他位被清零，但目标位仍留在第 i 位，结果是 0 或这个位的位权，不是固定的 0 或 1。

用户在 191 中曾写 res += n & (1<<i)。对 n=11（二进制 1011），实际累加如下：

| i | 掩码二进制 | 与结果 | 与结果的十进制值 |
|---|---|---|---|
| 0 | 0001 | 0001 | 1 |
| 1 | 0010 | 0010 | 2 |
| 2 | 0100 | 0000 | 0 |
| 3 | 1000 | 1000 | 8 |

高位均为 0，最终 res=1+2+8=11，累加的是原数字各位的权重，而不是 1 的数量。n&1 可直接累加，是因为最低位的位权就是 1，不能把这一点推广到任意位的掩码。

要计数，应把与结果转换为是否非零，再加一：

```cpp
// 本题 1<=n<=2^31-1，只需检查第 0 到第 30 位
int res = 0;
for (int i = 0; i < 31; ++i) {
    if ((n & (1 << i)) != 0) {
        ++res;
    }
}
```

也可以移动目标位到最低位后累加：

```cpp
for (int i = 0; i < 31; ++i) {
    res += ((n >> i) & 1);
}
```

以上两个代码片段是独立替代方案，分别从 res=0 开始，不能在同一次计数中接连执行。也可写 res += ((n & (1<<i)) != 0)，比较结果 false/true 在累加时变为 0/1；把整个按位与表达式加括号。

用户原循环检查 32 位并不是结果变成原数的原因，核心错误是直接累加了位权。本题只有 31 个有效位，示例只检查 0..30，避免涉及有符号最高位；完整 32 位的掩码操作可用 unsigned 类型及 1u<<i，同时确保移位次数小于类型位宽。

## 清除最低位的一个1

### 核心性质

对正整数 n，n&(n-1) 会清掉最右侧的一个 1，其他位保持不变：

```text
  n     = 1100
  n - 1 = 1011
  与结果 = 1000
```

减一把最右侧的 1 变成 0，它右侧的 0 变成 1；左侧不变。与原数做按位与后，右侧原本的 0 仍是 0，最低位的那个 1 被清掉，左侧保持原样。

### 在191中使用

```cpp
int countOnesByClearing(int n) {
    int res = 0;
    while (n > 0) {
        n &= (n - 1);
        ++res;
    }
    return res;
}
```

例如 13：

```text
1101 -> 1100 -> 1000 -> 0000
```

每轮清一个 1，一共三轮，所以答案为 3。while 在运算前保证 n>0，避免把正整数的推导直接套到负数上。

### 两种计数方法的区别

| 方法 | 每轮处理 | 循环次数 |
|---|---|---|
| 逐位检查 | 一个位，包括 0 | 有效二进制位数 b |
| 清除最低位 1 | 一个 1 | 1 的个数 k |

逐位检查时间 O(log n)，清位时间 O(k)，两者额外空间 O(1)。对于固定 32 位整数，也可以按固定宽度说两者都是常数时间。本题 n<=2^31-1，最多 31 个有效位。

用户反馈通过的是清位方法；逐位检查是补充参考。两种实现此前已在本地 C++17 的 110104 次输入检查中与独立参考一致，详见 [191 题目笔记](2026-10-04/0191-number-of-1-bits.md)。本次文档整理没有重新运行这批测试。

记忆时把三个动作分开：

```cpp
n & 1          // 取最低位
n >>= 1        // 移到下一位
n &= (n - 1)   // 清最低位的一个 1
```

### 在231中先用逐位计数判断

正整数是 2 的幂，当且仅当其二进制中只有一个 1：1、2、4、8、16 分别为 1、10、100、1000、10000。用户先尝试右移统计，最后判断 cnt==1；这个思路可行，但最初将取位写成了 cnt += m*1。

m*1 是乘法，结果仍为整个 m；m&1 才是检查最低位，结果为 0 或 1。n=16 时原代码执行如下：

| 本轮 m | m*1 | 累加后的 cnt | 本轮最低位 m&1 |
|---|---|---|---|
| 16 | 16 | 16 | 0 |
| 8 | 8 | 24 | 0 |
| 4 | 4 | 28 | 0 |
| 2 | 2 | 30 | 0 |
| 1 | 1 | 31 | 1 |

原代码得到 31，所以 cnt==1 为 false。它累加的是各次右移后的整数，而不是 1 的数量；较大的正数还可能使这种整数累加溢出。

本题允许 0 和负数，它们都不是 2 的幂。不能直接照搬前面正整数题目的 while(m) 右移计数，应先 if(n<=0) return false。常见的有符号算术右移实现中，负数最终可能停在 -1，-1 右移后仍是 -1，不能依赖它变成 0 来结束循环。

#### 修正取位后：为什么 -16 仍有问题

用户已将取位改为 cnt += m&1，但没有加入非正数保护。此时取位本身正确，问题是循环的终止条件：while(m) 等价于 while(m!=0)，不是 while(m>0)，因此负数也会进入。

在有符号算术右移的实现中，变化为：

```text
-16 -> -8 -> -4 -> -2 -> -1 -> -1 -> ...
```

右移会保留负数的符号，左侧补 1。仅用 8 位示意，实际 int 使用完整类型位宽：

```text
-16  11110000
 -8  11111000
 -4  11111100
 -2  11111110
 -1  11111111  -> 再右移仍全是 1
```

因此 m 无法变成 0，循环不能正常结束；到 -1 后每轮 m&1 为 1，cnt 持续增加，还可能最终触发有符号整数溢出。不能把这个现象简单理解为“统计出了错误个数”。有符号算术右移及符号扩展规则可参见 [C++ 工作草案：移位运算](https://eel.is/c++draft/expr.shift)；不要将当前草案规则不加区分地套用到所有旧语言版本。

2 的整数幂一定为正数，所以在循环前直接排除 n<=0。不要先取绝对值，否则会把 -16 当成 16，错误地判为 true。修正只需增加输入保护，已有取位和右移语句无需再改。

保留用户循环结构的修正参考：

```cpp
bool isPowerOfTwo(int n) {
    if (n <= 0) return false;

    int cnt = 0;
    int m = n;
    while (m) {
        cnt += (m & 1);
        m >>= 1;
    }
    return cnt == 1;
}
```

1=2^0 应返回 true；16 只计数一次，返回 true；3=11 有两个 1，返回 false。此方法按有效位数循环，时间 O(log n)、空间 O(1)，尚未满足不用循环或递归的进阶要求。先理解取位与输入范围，再学习进阶方法。

### 在231中直接判断只有一个1

2026-10-05 对照用户完整贴出的 [力扣官解方法一](https://leetcode.cn/problems/power-of-two/solutions/796201/2de-mi-by-leetcode-solution-rny3/)。核心条件仍是“正整数且二进制恰好一个 1”，不再用循环统计所有位，而是一次检查清位或提取位的结果。

#### 清掉最低位的1后是否为零

此前 191 的 n&(n-1) 每次清掉一个 1；231 中只做一次，如果已经没有 1，说明原来恰好一个。最低位的 1 指从右向左遇到的第一个 1，不一定是第 0 位。

```text
16：  00010000        12：  00001100
15：& 00001111        11：& 00001011
      --------            --------
      00000000            00001000
```

16 原来只有一个 1，清掉后得到 0；12 原来两个 1，清掉右侧那个后仍有一个。减一会让最低位 1 变 0、其右侧的 0 全变 1，高位不变；按位与后刚好只删除最低位 1。

```cpp
bool isPowerOfTwo(int n) {
    return n > 0 && (n & (n - 1)) == 0;
}
```

#### 只保留最低位的1后是否等于原数

n&(-n) 保留最低位的 1、清掉其他所有位。结果是该位的位权，不是计数，也不是一定返回 0/1。以正数 12 的 8 位补码示意：

```text
 n=12：       00001100
 全部取反：    11110011
 加 1 得 -12： 11110100

              00001100
           &  11110100
              --------
              00000100  = 4
```

取反后，原来最低位 1 右侧的 0 变成一串 1；加一时这串 1 连续进位变 0，直到原来最低位 1 对应的位置由 0 变回 1，进位停止。于是该位和右侧 0 与原数一致，高位与原数相反。做按位与，高位都变 0，只留下这个最低位 1。

12 提取后得到 4，不等于 12，说明还有其他 1；16 只包含一个 1，提取后仍是 16：

```text
 16：  00010000
-16：& 11110000
       --------
       00010000 = 16
```

```cpp
bool isPowerOfTwo(int n) {
    return n > 0 && (n & (-n)) == n;
}
```

官解写 n&-n 时，-n 是取相反数；加上括号写成 n&(-n) 更便于阅读。不要与 n&1 混淆：n&1 只检查第 0 位，12 的结果为 0；n&(-n) 找到从右侧开始的第一个 1，12 的结果为 4。

#### 正数保护与两种判断的区别

两种代码都必须保留 n>0。`(0 & (0 - 1)) == 0` 和 `(0 & (-0)) == 0` 都会让单独的位判断成立，但 0 不是 2 的幂。负数也应排除。

C++ 内置 && 有短路行为：先判断左边，若 n>0 为 false，右侧不执行。这同时使 INT_MIN 输入不会计算 n-1 或 -n，避免有符号溢出；不能把 && 换成 &，或先在保护之前计算这些表达式。[C++ 工作草案：逻辑与](https://eel.is/c++draft/expr.log.and)

| 操作 | 意义 | 在231中判断 |
|---|---|---|
| n&(n-1) | 清除最低位的一个 1 | 清完为 0 |
| n&(-n) | 只保留最低位的一个 1 | 提取后等于 n |

在固定宽度整数模型下，两种判断都只做常数次运算，时间 O(1)、空间 O(1)，满足不用循环或递归的进阶要求。推荐先熟悉已在 191 用过的清位判断，再理解提取位。仅对照所贴官解、手动推演与语义核对，没有新增编译测试或用户提交通过反馈。

### 位运算遇到比较时的括号

2026-10-05 用户实现了先排除非正数、再清位判断的版本；逻辑正确，尚未明确反馈提交通过：

```cpp
bool isPowerOfTwo(int n) {
    if (n <= 0) return false;
    return (n & (n - 1)) == 0;
}
```

用户此前遗漏按位与整体的括号。C++ 的 `==` 优先级比二元按位与 `&` 高，所以两种写法的分组不同：

```cpp
return n & (n - 1) == 0;    // 实际分组：n & ((n - 1) == 0)
return (n & (n - 1)) == 0;  // 需要的分组：清位结果再与 0 比较
```

例如 n=16，错误版先得到 `15 == 0` 为 false，参与整数按位与时转换为 0，因此 `16 & 0` 为 0，返回 false；正确版 `16 & 15` 为 0，再比较 `0 == 0`，返回 true。仅 n=1 的正数会让错误版返回 true，不能凭一个测试判断正确。

`(n-1)` 只把减法分组，不能保护整段按位与。相反，`if (n <= 0)` 的括号只是条件的边界，同样不会改变内部的优先级。记忆规则是：先位运算，再比较，位运算整体加括号。

```cpp
(n & 1) == 0                 // 检查最低位是否为 0
(n & (n - 1)) == 0           // 清位结果是否为 0
(n & (-n)) == n              // 提取最低位 1 后是否还是原数
(n & (1u << k)) != 0         // 检查第 k 位，k 必须合法
```

最后一行以 n 为非负整数为例，掩码使用 unsigned；不要写 `n & (1u << k) != 0`，它实际是 `n & ((1u << k) != 0)`，对合法 k 相当于检查 n 的最低位，而不是第 k 位。

也可以先拆出中间变量，按思路写清楚：`int cleared = n & (n - 1); return cleared == 0;`，前提是已排除非正数。常用运算符的优先级、结合性与求值顺序区别见 [语法速查](01-cpp语法知识文档.md#317-运算符优先级与括号)。规则依据 [C++ 按位与语法](https://eel.is/c++draft/expr.bit.and) 与 [相等比较语法](https://eel.is/c++draft/expr.eq)。本轮只作语义核对与手动模拟，未新增编译测试。

## 在338中复用计数结果

2026-10-05 学习 338 比特位计数。状态定义：bits[i] 是整数 i 的二进制表示中 1 的个数，不是 i 的二进制位数、某一位的下标或某一位的数值。bits[0]=0，从 1 到 n 计算，数组长度为 n+1。

### 用户逐个清位计数的版本

```cpp
class Solution {
public:
    int count1(const int& n) {
        int m = n;
        int res = 0;
        while (m) {
            m = m & (m - 1);
            ++res;
        }
        return res;
    }

    vector<int> countBits(int n) {
        vector<int> res(n + 1);
        for (int i = 0; i <= n; ++i) {
            res[i] = count1(i);
        }
        return res;
    }
};
```

每次清掉一个 1，因此 count1(i) 的实际循环次数等于 i 的 1 的个数；正数 i 的二进制位数为 floor(log2 i)+1，是循环次数的上界。15=1111 要循环 4 次，16=10000 只循环 1 次，不是每个输入都执行 log 次，也不是每轮必定除以 2。count1(0) 不进入循环。按题目数值规模估计，逐个统计的总时间通常写 O(n log n)，n=0 时是常数时间；返回数组占 O(n)，除此之外辅助空间 O(1)。代码逻辑正确，尚未明确反馈力扣通过。

### 三种DP共同的思路

来源为用户完整贴出的 [力扣官解方法二至四](https://leetcode.cn/problems/counting-bits/solutions/627418/bi-te-wei-ji-shu-by-leetcode-solution-0t1i/)。它们都把 i 变成某个更小的数 j，再复用已算好的 bits[j]，而不是继续循环计算 j 的计数。下面先讲与用户代码最接近的官解方法四，再讲方法三、方法二；不是更换官方编号。

三种依赖都满足 0<=j<i，因此从小到大遍历时，查表项已经计算完成。vector<int> bits(n+1) 将元素初始化为 0；n=0 时不进入循环，直接返回 [0]。

### 官解方法四 清掉最低设置位

i&(i-1) 把最右边的一个 1 清掉。以 13=1101 为例，清位后得到 12=1100；12 的答案已知为 2，所以 13 的答案是 2+1=3。

```cpp
vector<int> countBits(int n) {
    vector<int> bits(n + 1);
    for (int i = 1; i <= n; ++i) {
        bits[i] = bits[i & (i - 1)] + 1;
    }
    return bits;
}
```

与原 count1 的关键区别：原函数对 13 自己执行 13->12->8->0 共 3 轮；DP 只执行 13->12 这一步，再直接读取 bits[12]。它用之前的答案替代后面的循环，不是只把循环写法缩短。

最低设置位是最右边的 1，不一定是末尾第 0 位。官解中 10=1010 的最低设置位为 2，指位权 2，对应的位下标是 1，不是第 2 位；清掉它得到 8。

### 官解方法三 去掉最低二进制位

i>>1 去掉最右边的一位；i&1 判断被去掉的这一位是 0 还是 1。末尾 0 被去掉时计数不变，末尾 1 被去掉时需要加 1：

```cpp
vector<int> countBits(int n) {
    vector<int> bits(n + 1);
    for (int i = 1; i <= n; ++i) {
        bits[i] = bits[i >> 1] + (i & 1);
    }
    return bits;
}
```

13=1101，右移后为 6=110，bits[13]=bits[6]+1=3；12=1100，右移后也是 6=110，但 bits[12]=bits[6]+0=2。要区分“末尾的一位”和方法四的“最右边的一个 1”。(i&1) 保留括号：加法比按位与优先，不能把代码写成 bits[i>>1]+i&1。

### 官解方法二 去掉最高有效位

highBit 是不超过 i 的最大 2 的幂，是位权而不是位下标或 1 的数量。例如 13=1101 的 highBit 是 8=1000，而不是下标 3；i-highBit=5=0101，刚好去掉最左边的那个 1，所以 bits[13]=bits[5]+1=3。

```cpp
vector<int> countBits(int n) {
    vector<int> bits(n + 1);
    int highBit = 0;
    for (int i = 1; i <= n; ++i) {
        if ((i & (i - 1)) == 0) {
            highBit = i;
        }
        bits[i] = bits[i - highBit] + 1;
    }
    return bits;
}
```

从小到大遍历，在 i=1、2、4、8、16 等 2 的幂处，才会出现新的最高位，highBit 更新为 i；同一段其他整数继续使用这个值。例如 i=4..7 时 highBit 一直是 4，i=8..15 时一直是 8。在 i=1 的第一轮，先更新 highBit=1，再访问 bits[0]；不能调换这两条操作的顺序。判断 2 的幂直接复用此前 231 的 `(i & (i-1)) == 0`，遍历从 1 开始，无需额外排除 0。

### 对照和复杂度

| 官解方法 | 从 13=1101 得到的小问题 | 要补回的计数 |
|---|---|---|
| 方法二 最高有效位 | 去掉 8，剩 5=0101 | +1 |
| 方法三 最低有效位 | 右移一位，剩 6=0110 | +(13&1)，本例是 +1 |
| 方法四 最低设置位 | 清掉末尾的 1，剩 12=1100 | +1 |

每个 i 只进行常数次位运算和数组访问，不继续搜索或循环计数，因此三种 DP 都是 O(n) 时间。数组本身占 O(n) 空间；官解的 O(1) 空间指不计返回数组的辅助空间，方法二也只多一个 highBit。推荐先独立重写方法四，再理解方法三，不强制立刻背下三种公式。

此前用 JavaScript 行为模型对三种递推在 0..100000 的全部 100001 个整数进行核对，参考答案独立从二进制字符串统计 1，三种结果全部一致；n=0 返回 [0]，n=5 返回 [0,1,1,2,1,2]，13 的计数为 3。该轮属于递推模型验证，不是 C++ 编译运行，也不等于用户力扣提交通过反馈。

## 在268中让两组数字抵消

2026-10-05 用户参考题解写出双循环异或实现，逻辑正确，尚待力扣提交反馈。完整代码和验证见 [268 日期笔记](2026-10-05/0268-missing-number.md)。

把 nums 的所有元素与完整范围 0..n 的所有数字一起异或。每个已出现的数字恰好有两份，利用 a^a=0 抵消；缺失的数字只在完整范围中出现一次，所以最终只剩它。与 136 的区别是：136 在同一数组中抵消成对数字，本题用两组数字形成对应的两份。

```text
nums=[3,0,1]
(3 ^ 0 ^ 1) ^ (0 ^ 1 ^ 2 ^ 3)
= (3 ^ 3) ^ (0 ^ 0) ^ (1 ^ 1) ^ 2
= 2
```

第一个循环访问数组，i<n；第二个循环生成完整范围，i<=n。完整范围比数组多一个数，不能漏掉 n。缺失 0 或 n 都无需特殊处理。两个循环依次执行，共 2n+1 次，时间 O(n)、额外空间 O(1)，不是嵌套循环的 O(n²)。

可选地令 res=n，在一轮循环中依次 res^=i、res^=nums[i]，相当于把完整范围的最后一个 n 提前处理；它与双循环复杂度相同，原版本无需改写。下标 i 只负责生成范围，不要求数组有序或 nums[i]==i。

此前一轮 C++17 对用户双循环与单循环参考共核对 47244 个合法输入，与独立存在标记法一致，并检查输入不被修改。双循环是用户实现，单循环仅为助手参考，本地验证不等于力扣通过或独立熟练掌握。

## 在260中按差异位分组

用户已修正 mask<<=1 和分组 !=0，明确反馈 260 力扣通过。全部异或后只剩 diff=a^b，不能直接还原两个未知数字。a、b 不同，所以 diff 至少有一个 1；选择其中一位为 mask，按 `(num & mask) == 0` 与非零分组。两个单次数字进不同组，每对相同数字进同一组，分别异或后得到两个答案。

示例 [1,2,1,3,2,5] 中 diff=6=0110，选择 mask=2=0010，零组 [1,1,5] 得 5，非零组 [2,3,2] 得 3。分组只是逻辑划分，实际维护两个累计变量，不建立两个数组。先用 unsigned int mask=1u，从低到高循环左移，找到 diff 中为 1 的位；固定 32 位至多左移 31 次，适应负数与符号位。分组判断非零而非 ==1，保留整体按位与的括号；不要直接对有符号 INT_MIN 求负来提取最低位。

记忆句：先异或找不同，再按一位分两组，组内成对抵消。两个遍历 O(n)，其他辅助空间 O(1)。完整推导、用户通过版与边界见 [260 日期笔记](2026-10-05/0260-single-number-iii.md)。首次引导的 JavaScript 32 位模型核对 168 个输入一致；最新通过依据为用户明确反馈及静态代码审查，本轮没有新增本地编译或测试。

## 常见易错点

260 首版重现两个易错点：mask<<1 未赋回变量，xorsum=6、mask=1 时 while 条件一直成立；修正为 mask<<=1 后，mask=2，num&mask 的结果为 0 或 2，分组必须判断 !=0，而不是 ==1。用户报告 [6,0] 对应以 mask=1 分组的结果，不符合贴出完整循环的正常执行路径；只修移位但保留 ==1 会得 [0,6]，两处修正的模型得 [3,5]。本轮有界模型未运行无界错误循环，没有新增 C++ 编译或通过反馈。

- * 是乘法，m*1 仍是 m；& 才是按位与，m&1 只取最低位。
- ^ 是异或，不是乘方。3^2 得 1，不是 9。
- & 与 && 不同。2&1 得 0，2&&1 得 true；前者逐位运算，后者判断两个操作数是否非零。
- | 与 || 不同，前者按位或，后者逻辑或。
- 单独写 n>>1 不会修改 n。循环中需要 n>>=1 或 n=n>>1。
- ~ 会翻转整个计算类型的所有位，不能只按画出来的四位判断结果；小整数类型还可能先发生整数提升。
- 使用类型和范围约束。这里的 int 清位和右移计数以非负数为前提；完整位模式操作通常用 unsigned，不能认为换一个类型就忽略所有边界。
- 移位次数必须合法。负数次数，或不小于提升后左操作数位宽的次数，会产生未定义行为。
- 负数移位要区分语言版本：C++17 的有符号负数左移未定义，负数右移由实现定义；不要把常见硬件行为直接当成所有版本的 C++ 保证。
- 判断取位结果时加括号，例如 `(x & mask) != 0`，避免与比较运算混在一起时误读优先级。
- n&mask 是保留对应位置，可能得到 2、8 等位权；计数时先判断非零，或写 `(n>>i)&1` 得到 0/1。
