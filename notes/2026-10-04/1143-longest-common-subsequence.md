# 1143. 最长公共子序列

2026-10-04 用户在二维前缀 DP 中补上字符不相等时的状态转移后，明确反馈力扣通过。本题重点是前缀最优答案可以跳过不匹配字符，状态不要求以两个当前字符结尾。

## 用户通过代码

```cpp
class Solution {
public:
    int longestCommonSubsequence(string text1, string text2) {
        int m = (int)text1.size();
        int n = (int)text2.size();
        int res = 0;

        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));

        for (int i = 0; i < m; ++i) {
            dp[i][0] = 0;
        }
        for (int j = 0; j < n; ++j) {
            dp[0][j] = 0;
        }

        // 递推公式
        for (int i = 1; i <= m; ++i) {
            for (int j = 1; j <= n; ++j) {
                if (text1[i-1] == text2[j-1]) {
                    dp[i][j] = dp[i-1][j-1] + 1;
                } else {
                    dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
                }
                res = max(res, dp[i][j]);
            }
        }
        return res;
    }
};
```

## 状态、初始化与顺序

dp[i][j] 表示 text1 的前 i 个字符与 text2 的前 j 个字符的最长公共子序列长度。i、j 是前缀长度，最后一个字符的下标分别为 i-1、j-1。

子序列允许跳过字符，但不能改变顺序。这里没有“必须使用两个前缀末尾字符”的要求，也不是要求连续的公共子串。例如 "ab" 与 "a" 的最长公共子序列仍为 "a"，所以 dp[2][1]=1，不能因末尾不同就置零。

第一行或第一列对应一边为空字符串，公共子序列长度为 0，因此分配 (m+1)×(n+1) 的表，并把第 0 行、第 0 列视为基础情况。当前构造函数已将整个表初始化为 0，后面的两个清零循环可以删除。虽然这两个循环分别只到 m-1、n-1，但遗漏位置本来也是 0，不是当前错误。

递推依赖左上、上方和左方状态，按行从上到下、每行从左到右计算，三者在使用前均已完成。

## 两种递推情况

| 当前末尾字符 | 转移 | 含义 |
|---|---|---|
| text1[i-1]==text2[j-1] | dp[i-1][j-1]+1 | 在两个更短前缀的答案后接上这一对匹配字符 |
| 两者不相等 | max(dp[i-1][j],dp[i][j-1]) | 跳过其中一边的末尾字符，保留较好的结果 |

末尾字符不同时，公共子序列不能同时把这两个不同字符作为最后一对匹配，至少有一边末尾未被使用。分别考虑不使用 text1 的末尾和不使用 text2 的末尾，取两种情况中的较大值。

最终 dp[m][n] 表示两个完整字符串的答案，可以直接返回。用户维护 res 的写法也正确，因为任意前缀的公共子序列都是完整字符串的公共子序列，dp[m][n] 不小于任何其他状态。这与“必须以当前位置结尾”的 DP 不同，不必再单独维护历史最大值。

## 首版为何得到 1

用户首版只有字符相等分支，不相等时状态留在初始值 0。按题目示例 text1="abcde"、text2="ace" 推演：

```text
dp[1][1] = 1                // "a" 与 "a"
dp[2][1] 错误地保留为 0     // "ab" 与 "a" 应为 1
dp[3][2] = dp[2][1]+1 = 1   // 匹配 'c'，但之前的 'a' 丢失
dp[4][2] 错误地保留为 0     // "abcd" 与 "ac" 应为 2
dp[5][3] = dp[4][2]+1 = 1   // 匹配 'e'，前面的 "ac" 丢失
```

补上不相等分支后，跳过 'b' 和 'd' 时可以继承已有答案，得到正确的表：

| text1 前缀 / text2 前缀 | 空串 | a | ac | ace |
|---|---:|---:|---:|---:|
| 空串 | 0 | 0 | 0 | 0 |
| a | 0 | 1 | 1 | 1 |
| ab | 0 | 1 | 1 | 1 |
| abc | 0 | 1 | 2 | 2 |
| abcd | 0 | 1 | 2 | 2 |
| abcde | 0 | 1 | 2 | 3 |

## 精简参考

删除重复清零和 res，直接返回完整前缀的状态。此处为逻辑等价的学习参考，不是用户另外一次力扣提交反馈。

```cpp
class Solution {
public:
    int longestCommonSubsequence(string text1, string text2) {
        int m = (int)text1.size();
        int n = (int)text2.size();
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));

        for (int i = 1; i <= m; ++i) {
            for (int j = 1; j <= n; ++j) {
                if (text1[i-1] == text2[j-1]) {
                    dp[i][j] = dp[i-1][j-1] + 1;
                } else {
                    dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
                }
            }
        }
        return dp[m][n];
    }
};
```

## 与用户贴出的官解对照

用户随后贴出完整官方说明与代码，请求比较。两份代码的状态、递推公式和遍历顺序完全相同，主要差别是初始化、答案返回和字符访问的写法。对照依据用户提供的内容，没有另行浏览网页或把官解当成用户另一次提交反馈。

| 对照点 | 用户通过版 | 官解 |
|---|---|---|
| 表初始化 | vector<int>(n+1,0)，随后又清零首行首列 | vector<int>(n+1) 已将 int 元素初始化为 0，无需再次清零 |
| 答案 | 每轮维护 res，最终返回 res | 直接返回 dp[m][n] |
| 字符访问 | text1[i-1]、text2[j-1] | text1.at(i-1)、text2.at(j-1) |
| 局部字符 | 直接在条件中取字符 | c1 在外层取一次，c2 在内层取出，比较更清楚 |
| 字符串长度 | size() 并显式转换为 int | length() 并赋给 int；在本题长度上限下结果相同 |

vector<int>(n+1) 的元素会被初始化为 0，所以这里省略第二个构造参数不意味着 dp 中是随机值。两种构造方式与边界结果相同。

任意两个前缀中的公共子序列也是两个完整字符串的公共子序列，因此 dp[m][n] 不小于表中的任何其他值。res 保存的最大值与 dp[m][n] 相等；省略 res 是精简，不是用户的算法错误。

string::at(pos) 会检查下标，pos>=size() 时抛出 std::out_of_range。当前循环保证 i-1 位于 0..m-1、j-1 位于 0..n-1，at() 与 [] 均读取同一字符。不要把 [] 的非法访问描述为一定崩溃；本题的访问均合法。字符串下标边界的完整说明见 [C++ 语法速查](../01-cpp语法知识文档.md)。

外层固定 i 时，text1[i-1] 不随 j 改变，官解在内层循环前把它复制到 char c1；这是局部字符副本，用于读取与比较，不是引用。c2 同样复制当前 text2 字符。这个写法不改变 DP 的逻辑，也不改变 O(mn) 的时间与空间复杂度。

用户贴出的说明中，text1[0:i] 被定义为前 i 个字符，即数学记号中的半开前缀，末尾实际下标是 i-1；它不是 C++ 的切片语法。该贴文“不相等时考虑两项”的下标描述出现 i-2、j-2，与前面的长度定义和后面的正确公式不一致。按前缀长度含义，正确的两项应是：

| 状态 | text1 的范围 | text2 的范围 |
|---|---|---|
| dp[i-1][j] | 前 i-1 个字符，即 text1[0:(i-1)] | 前 j 个字符，即 text2[0:j] |
| dp[i][j-1] | 前 i 个字符，即 text1[0:i] | 前 j-1 个字符，即 text2[0:(j-1)] |

这是所贴文字的下标表述问题，官解实际代码 max(dp[i-1][j],dp[i][j-1]) 与用户代码均正确。读代码时把 i、j 解释为前缀长度，再用 i-1、j-1 访问字符，可以避免把长度与末尾下标混用。
