# 461 汉明距离

2026-10-04 用户自行实现“异或加清除最低位 1”，并明确反馈力扣通过。它把此前 191 的计数方法用于两个整数的比较，是位运算学习计划中的第二题。本题按补充练习收录，不声称属于 Hot 100 原清单。

## 用户通过代码

```cpp
class Solution {
public:
    int hammingDistance(int x, int y) {
        int num = x ^ y;
        int res = 0;

        while (num) {
            ++res;
            num &= (num - 1);
        }

        return res;
    }
};
```

## 从不同位转成位计数

异或按对应位计算：相同得 0，不同得 1。因此 x^y 的每个 1 都对应一处差异；异或结果的数值不是距离，还需要统计其中 1 的个数。

```text
x = 1：0001
y = 4：0100
x ^ y：0101
```

结果的数值是 5，但其中只有两个 1，所以汉明距离是 2。清位过程为 0101 -> 0100 -> 0000，每轮删除一个 1，res 最终为 2。

191 是“统计一个数中的 1”；461 先把两个数异或，再做同样的计数。记忆：异或标出不同位，清位统计不同位的数量。

## 与官解的对照

[力扣官方题解](https://leetcode.cn/problems/hamming-distance/solutions/797339/yi-ming-ju-chi-by-leetcode-solution-u1w7/)介绍三种位计数方式，均先计算 x^y：

| 方法 | 统计方式 | 与用户实现的关系 |
|---|---|---|
| 方法一 内置位计数 | 使用 __builtin_popcount | 直接调用计数功能 |
| 方法二 移位计数 | 检查最低位，再右移一位 | 逐个检查位，包括 0 |
| 方法三 Brian Kernighan 算法 | 每轮清掉最低位的一个 1 | 与用户实现相同 |

方法三中，官解先清位再增加计数，用户先增加计数再清位。两者每轮都完成一次清位和一次加一，顺序不影响结果；变量名不同、独立语句中的前置与后置自增也不影响最终计数。

方法二的等价学习参考（不是另一次用户提交）：

```cpp
int hammingDistanceByShift(int x, int y) {
    int remaining = x ^ y;
    int differentBits = 0;
    for (; remaining != 0; remaining >>= 1) {
        differentBits += (remaining & 1);
    }
    return differentBits;
}
```

该方法每次检查当前最低位，再把剩余部分右移；不能只写 remaining>>1 而不赋值。对 0101，清位循环 2 次，逐位检查循环 3 次。不要仅凭循环次数推断所有环境下的实际运行速度。

方法一的 C++ 写法：

```cpp
return __builtin_popcount(x ^ y);
```

根据 [GCC 文档](https://gcc.gnu.org/onlinedocs/gcc/Bit-Operation-Builtins.html)，__builtin_popcount 接收 unsigned int，返回其中 1 的数量。这是编译器内置功能，不是普通标准库容器成员；使用其他编译环境时要确认是否支持。当前学习重点仍是理解手写计数的原理。

## 边界与复杂度

- x==y 时，异或结果为 0，循环不执行，返回 0；x=y=0 同样成立。
- 一个输入为 0 时，距离等于另一个输入的 1 的个数。
- 输入范围为非负的 31 位有效整数，异或结果也非负；最多有 31 个 1，int 足够存储答案。
- 设异或结果有 k 个 1、b 个有效位，清位循环执行 k 次，逐位方法执行 b 次；两者最坏均为 O(log C)，C 是输入值域上界，额外空间均为 O(1)。固定 32 位模型下也可按常数时间理解。
