# 191 位1的个数

2026-10-04 用户看懂官解方法二后自行实现，并明确反馈力扣通过。本笔记记录清除最低位 1 的性质，以及从基础运算推导的逐位检查写法。本题是位运算补充练习，不属于 Hot 100 原题清单。

## 用户通过代码

```cpp
class Solution {
public:
    int hammingWeight(int n) {
        int res = 0;
        while (n) {
            n &= (n - 1);
            ++res;
        }
        return res;
    }
};
```

while(n) 在这里等价于 while(n!=0)。n &= (n-1) 等价于 n = n & (n-1)，必须修改 n，才能继续清除其余的 1。

## 清除最低位 1 的性质

对正整数 n，n & (n-1) 恰好清除二进制中最右侧的一个 1，其他位保持不变。它不是取出最低位的值，也不是简单右移。

例如 n=12：

```text
  n     = 1100
  n - 1 = 1011
  与结果 = 1000
```

减一时，最低位的 1 变为 0，它右侧的所有 0 变为 1；左侧的位保持原样。再与原数做按位与：左侧不变，原来的最低位 1 被清零，右侧原本的 0 仍为 0。

对 n=13，反复执行：

```text
1101 -> 1100 -> 1000 -> 0000
```

一共清除三个 1，因此 res=3。已清除的 1 数量加上当前 n 中剩余的 1 数量，始终等于原数中 1 的总数量；n 变为 0 时，res 就是答案。

while 保证运算前 n>0，本题正整数范围下 n-1 不会溢出。不把这份有符号 int 写法无条件推广到负数。

## 通用的逐位检查写法

不需要先想到清位技巧：先检查最右边一位，再右移，让下一位来到最右边。

```cpp
class Solution {
public:
    int hammingWeight(int n) {
        int res = 0;
        while (n > 0) {
            res += (n & 1);
            n >>= 1;
        }
        return res;
    }
};
```

n & 1 只保留最低位，结果为 0 或 1；累加这个结果等价于最低位为 1 时 ++res。n >>= 1 等价于 n = n >> 1，会修改 n。单独写 n >> 1 只计算，不修改变量。

这里的 n 为非负整数，右移一位等价于整数除以 2。遇到符号位、负数或移位范围问题时，需要重新检查类型约束；按完整位模式操作时通常使用 unsigned 类型。

| 当前二进制 | n & 1 | 处理后 res | 右移后 |
|---|---|---|---|
| 1101 | 1 | 1 | 0110 |
| 0110 | 0 | 1 | 0011 |
| 0011 | 1 | 2 | 0001 |
| 0001 | 1 | 3 | 0000 |

本写法是补充参考，用户尚未反馈它在力扣另一次提交通过；本地已与用户方法一起验证。

## 两种方法与记忆

| 方法 | 一轮处理 | 循环次数 |
|---|---|---|
| 清除最低位 1 | 一个 1 | k 次，k 为原数中 1 的个数 |
| 逐位检查并右移 | 一个二进制位 | b 次，b 为正整数的二进制位数 |

清位方法时间 O(k)，逐位方法时间 O(log n)，两者额外空间 O(1)。本题最多 31 个有效位，若把整数宽度看作固定常数，两者也都可以说是常数时间；学习时用 k 和 b 表达循环次数更清楚。清位方法循环次数不超过逐位方法，但不能仅据此断言所有环境下的实测速度。

记忆：取最低位用 n&1，移到下一位用 n>>=1，清掉最低位的 1 用 n&=(n-1)。

## 后续固定位置扫描的错误

用户尝试 for(i=0;i<32;++i) res += n&(1<<i)，结果错误。1<<i 是只保留第 i 位的掩码，与结果可能是 0 或 1、2、4、8 等位权，不能直接当作该位是否为 1 的数量累加。

例如 n=11=1011，i=0、1、2、3 得到 1、2、0、8，其余高位为 0，累加结果 11，而答案是 3。检查最低位时 n&1 只得 0/1，但任意位置的掩码需要额外判断。

保留用户 for 循环思路的修正参考：

```cpp
class Solution {
public:
    int hammingWeight(int n) {
        int res = 0;
        for (int i = 0; i < 31; ++i) {
            if ((n & (1 << i)) != 0) {
                ++res;
            }
        }
        return res;
    }
};
```

本题 n<=2^31-1，只需检查第 0 到第 30 位。原循环多检查第 31 位不是主要错误，不把它误诊为当前错误答案的原因。完整 32 位掩码可使用 unsigned 和 1u<<i，并检查位宽约束。

另一种参考为 res += ((n>>i)&1)，先把目标位移到最低位再取 0/1；或 res += ((n&(1<<i))!=0)，先用比较归一化。固定扫描 31 次，空间 O(1)。本次仅静态审查与手动模拟，未新增 C++ 编译，尚未收到此改写修正后的力扣通过反馈，不能把此前清位实现的通过和测试算作新版本验证。

## 后续逐位扫描未推进的错误

用户改为先 res += m&1，再 for(i=1;i<32;++i) 累加 (m>>1)&1。当前取位结果是 0/1，但 m>>1 只计算，不修改 m；每轮仍以同一个原数右移一位，重复检查原数第 1 位。

n=11=1011 时，循环前贡献 1，31 轮循环每轮贡献 1，合计 32 而非 3。这与前一版直接累加位权不同：这次错在扫描位置没有推进。

保留结构可在每轮先 m>>=1，再 res += (m&1)。也可以保持 m 不变，将循环内改为 res += ((m>>i)&1)。更新原数和增加移位距离是两种不同方式，不应混用。

详细代码见 [位运算总笔记](../02-位运算学习笔记.md)的“右移表达式不会修改原变量”。本次仅静态审查与手动模拟，未新增编译测试，也尚未收到本次修正后的力扣通过反馈；下方既有本地验证不属于这一固定轮数改写。
