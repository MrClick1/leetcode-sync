# 169. 多数元素（二刷）

状态：用户自行实现并明确反馈力扣通过；本轮静态审查与手工模拟，未新增本地编译测试。旧笔记见 [2026-08-16](../2026-08-16/0169-majority-element.md)，不重复增加不同题目数。

## 用户通过代码

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        int n = (int)nums.size();
        int res = nums[0];
        int cnt = 1;

        for (int i = 1; i < n; ++i) {
            if (cnt == 0) {
                res = nums[i];
                cnt = 1;
            } else {
                if (nums[i] == res) {
                    ++cnt;
                } else {
                    --cnt;
                }
            }
        }
        return res;
    }
};
```

## 状态与证明

- res 是当前候选人，不是每一步都已确定的最终答案。
- cnt 是已处理前缀中不同元素两两抵消后，当前候选人剩余的数量，不是候选人在原数组里的总出现次数。
- 相同则保留一票，不同则与候选人抵消一票；cnt 为 0 时，当前元素成为新候选人并取得第一票。
- 若多数元素有 M 个，其他元素共有 R 个，则 M > R。删除两个不同元素，若包含多数元素，M、R 同减 1；否则 R 减 2。多数元素的数量优势不会消失，最终非空剩余只可能是多数元素。
- 原数组非空且保证存在多数元素，故可直接返回 res；取消存在性保证时，必须再统计候选人的实际出现次数进行验证。

## 手动模拟

输入 [2,2,1,1,1,2,2]：

| 下标 | 当前数 | 处理后 res | 处理后 cnt | 动作 |
|---|---|---|---|---|
| 0 | 2 | 2 | 1 | 初始化 |
| 1 | 2 | 2 | 2 | 同值加票 |
| 2 | 1 | 2 | 1 | 不同抵消 |
| 3 | 1 | 2 | 0 | 不同抵消 |
| 4 | 1 | 1 | 1 | 重新选候选人 |
| 5 | 2 | 1 | 0 | 不同抵消 |
| 6 | 2 | 2 | 1 | 重新选候选人 |

返回 2。最终 cnt=1，但 2 实际出现了 4 次。

## 记忆与复杂度

口诀：没票换人，同人加票，异人减票。

时间 O(n)，额外空间 O(1)，输入不修改，满足进阶要求。初始化选取 nums[0] 并给一票，循环从 1 开始，二者对应一致。

与 136 异或不同：136 利用相同数字成对抵消；169 利用不同数字成对抵消且多数元素数量严格超过一半。本题不是异或算法。

## 与用户贴出的官解方法五对照

两者是同一个 Boyer–Moore 投票算法，不只是相似。

- 用户首元素初始化 res、cnt=1，再从下标 1 遍历；官解 count=0，从首元素开始，第一轮自动选首元素并加一票。处理首元素后状态一致。
- 用户在 cnt==0 分支中选新候选人并直接赋 cnt=1；官解先选新候选人，然后执行统一加减。当前数必等于新候选人，故同样从 0 加到 1。
- 其他情况下，同值加 1、异值减 1，最终返回候选人，时间 O(n)、额外空间 O(1)。

官解 Java 核心逻辑的 C++ 等价参考（不是另一种算法，也不替换用户通过代码）：

```cpp
int candidate = 0;
int count = 0;
for (int num : nums) {
    if (count == 0) {
        candidate = num;
    }
    count += (num == candidate) ? 1 : -1;
}
return candidate;
```

candidate 初值在这里没有实际作用：首次使用前必被首元素覆盖。Java 的 Integer/null 不需要照搬到本题 C++。

### 所贴证明的局限

“每一步 count 和 value 要么相等，要么互为相反数”不是一般性质。以合法输入 [1,2,3,3,3] 为例，真正多数元素是 3，value 始终按遇 3 加 1、非 3 减 1：

| 当前数 | candidate | count | value |
|---|---|---|---|
| 1 | 1 | 1 | -1 |
| 2 | 1 | 0 | -2 |
| 3 | 3 | 1 | -1 |
| 3 | 3 | 2 | 0 |
| 3 | 3 | 3 | 1 |

第二步 count=0、value=-2；最终 count=3、value=1，但算法仍正确返回 3。count 是不同元素抵消后的剩余票数，value 是真正多数元素在原前缀中的数量优势，不是同一统计量。

推导的问题：candidate 不是多数元素时，当前元素可能既不是 candidate，也不是多数元素，此时 count 和 value 都减 1，并非相反变化；前面已丢弃的零票段也可能改变全局 value。应记前文不同元素配对删除保持多数优势的证明，不依赖这项不成立的性质。

## 官解 C++：前置递减的紧凑写法

用户随后贴出的 C++ 官解仍是同一算法：

```cpp
int candidate = -1;
int count = 0;
for (int num : nums) {
    if (num == candidate)
        ++count;
    else if (--count < 0) {
        candidate = num;
        count = 1;
    }
}
return candidate;
```

--count 是先修改 count，再用修改后的值参与比较。第二个分支只有 num!=candidate 时才执行；等值加票时不会再递减。拆开等价于：

```cpp
if (num == candidate) {
    ++count;
} else {
    --count;
    if (count < 0) {
        candidate = num;
        count = 1;
    }
}
```

进入每轮前 count 非负。等值加票；异值且原 count>0 时减一，仍非负，代表抵消一个已有候选人；异值且原 count==0 时暂时变成 -1，立即改候选人并设为 1，当前元素取得第一票。这不是留下了负票。count 从 1 减到 0 时只抵消，不应在这一轮把已经抵消掉的当前元素再选为候选人；原条件严格 <0，不是 <=0。

| 进入本轮时 | 当前数与候选人 | 官解结果 | 用户原写法结果 |
|---|---|---|---|
| count>0 | 相同 | count+1 | count+1 |
| count>0 | 不同 | count-1 | count-1 |
| count==0 | 相同 | 原候选人得1票 | 重新赋相同候选人，得1票 |
| count==0 | 不同 | 0先减至-1，再换人设1 | 直接换人设1 |

candidate=-1 仅为可读的初始化值，不要求 -1 不在输入中。首元素为 -1 时直接加票，其他值则进入暂时负数分支选为候选人，两者都正确。

手动模拟 [3,2,3]：初始(-1,0)；读3时 count暂至-1 后重置为(candidate=3,count=1)；读2抵消至0；读3与保留的候选人相同，重新得到1票，返回3。

与用户版本复杂度完全相同，均为 O(n) 时间/O(1) 空间。这是控制流合并，不是算法上的进一步优化；学习时保留用户“没票换人，同人加票，异人减票”的显式版本即可。
