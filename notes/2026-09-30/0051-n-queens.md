## 题目要求

在 n×n 棋盘放置 n 个皇后，任意两个皇后不能同行、同列或同斜线，返回所有不同棋盘。Q 表示皇后，. 表示空位，1<=n<=9。n=4 有两组方案；n=1 为 [["Q"]]。

## 用户首版代码

```cpp
class Solution {
public:
    void backtracking(vector<vector<string>>& res, vector<string>& path,
                      int r, vector<vector<bool>>& valid, const int& n) {
        if (r == n) {
            res.push_back(path);
        }
        for (int c = 0; c < n; ++c) {
            if (valid[r][c] == true) {
                path[r][c] = 'Q';
                vector<vector<bool>> validCpoy(valid);
                for (int i = r; i < n; ++i) {
                    valid[i][c] = false;
                }
                for (int i = r; i < n; ++i) {
                    if (c - i + r >= 0 && c - i + r < n) {
                        valid[r][c - i + r] = false;
                    }
                }
                for (int i = r; i < n; ++i) {
                    if (c + i - r >= 0 && c - i + r < n) {
                        valid[r][c + i - r] = false;
                    }
                }
                backtracking(res, path, r + 1, valid, n);
                valid = validCpoy;
                path[r][c] = '.';
            }
        }
    }

    vector<vector<string>> solveNQueens(int n) {
        vector<vector<string>> res;
        vector<string> path(n);
        for (int i = 0; i < n; ++i) {
            path[i] = '.' * n;
        }
        vector<vector<bool>> valid(n, vector<bool>(n, true));
        backtracking(res, path, 0, valid, n);
        return res;
    }
};
```

## 一、附件所指的越界：到第 n 行仍继续搜索

附件完整报错已读取，顶部为 heap-buffer-overflow，READ of size 8，调用栈经 vector<bool> 的 operator[] 指向用户的 valid[r][c]。不是标准库需要修复，而是用户给出了非法行下标。

有效行号为 0..n-1。r==n 时已放完皇后，res.push_back(path) 后却没有 return；后面的 c 循环依然从 0 开始，因此立即访问 valid[n][0]。例如 n=1，保存 ["Q"] 后，仍试读不存在的第 1 行。

```cpp
if (r == n) {
    res.push_back(path);
    return;
}
```

与上一题 131 的区别：131 终点 startIndex==s.size() 时，for 的初始 i 就等于 size，循环不进入，缺少 return 仍可自然结束；本题循环条件只取决于列 c<n，和 r==n 没有关联，必须阻止继续访问棋盘。

原版还有下面几个独立的非法访问来源，不能据此认为只补 return 就全部正确。

## 二、棋盘没有初始化为 n 列

`'.' * n` 是字符参与整数乘法，不是重复字符。将该整数结果赋给 string 时，使用单字符赋值，得到长度为 1 的字符串，不是 n 个点。vector<string> path(n) 也仅创建 n 个空字符串，没有创建列。

直接构造：

```cpp
vector<string> path(n, string(n, '.'));
```

string(n,'.') 创建 n 个点的一行；外面的 vector 创建 n 份行字符串，构成 n×n 棋盘。随后 path[r][c] 才对应合法的棋盘单元格。各行是独立副本，不会因为修改一行而同步修改其他行。

不要笼统说旧写法 c=1 必然是普通数组越界：string 长度为 1 时该位置是终止字符，写成非零 Q 本身非法；c>1 则超出 string 下标要求。无论具体表现如何，都不是合法的 n 列棋盘。相关语法见 [C++ 语法笔记](../01-cpp语法知识文档.md)。

### 补上 return 后为什么仍出现 Q / � 等单字符行

用户中间版只补了 return，path[i]='.'*n 仍保留。vector<string> 中的元素类型没有改变：path[r] 是 string，path[r][c] 是 char。赋入错误的字符值不会把 string 变为其他类型。

本地 n=4 的 C++17 测试打印：'.'*n 的整数结果为 184，赋值后的行长度为 1，存入单个字节的无符号值为 184。该字节不是四个点，显示端按字符编码解码时可能显示替代符 �；不能把具体乱码显示当成 C++ 保证的结果。

当写 path[r][0]='Q' 时，只是把这行唯一的字符替换为 Q，字符串长度仍为 1，所以可能看到 "Q"，而不是 "Q..."。在后续非法下标写入之后，程序有未定义行为，不能把整份输出作为可信棋盘结果分析。

替换原来的声明和初始化循环为 vector<string> path(n,string(n,'.'))；若保留原有 for，只需把循环内赋值改为 path[i]=string(n,'.')。不要构造正确棋盘后又执行旧的字符乘法循环，把每行覆盖回单字符。

本轮只安全检查类型、初始字节、合法的第 0 字符替换以及正确棋盘各行独立，没有执行错误行的其他下标写入。初始化修好后，下面两项斜线问题仍需修正；return 仅修复终点继续访问第 n 行的问题。

## 三、斜线写入的行应该随 i 变化

皇后在 (r,c)，走到未来第 i 行时，向下走了 i-r 步：

- 左下列号为 c-(i-r)。
- 右下列号为 c+(i-r)。
- 写入的位置应为 valid[i][对应列号]，而不是 valid[r][对应列号]。

例如 n=4、皇后 (1,2)，左下为 (2,1)、(3,0)，右下只有 (2,3)；再向右下会到 (3,4)，超出棋盘。原版一直写第 r 行，没有屏蔽未来行的受攻击格子。

两段斜线可保留原有算式，也可将列号命名后放在一个循环里，减少检查与访问的错配：

```cpp
for (int i = r + 1; i < n; ++i) {
    int leftCol = c - (i - r);
    int rightCol = c + (i - r);
    if (leftCol >= 0 && leftCol < n) {
        valid[i][leftCol] = false;
    }
    if (rightCol >= 0 && rightCol < n) {
        valid[i][rightCol] = false;
    }
}
```

从 r+1 开始只标记后面尚未摆皇后的行；原先从 r 开始也可以，只要坐标和边界正确，包含皇后自己那一格并非主要错误。列标记的 valid[i][c] 原有思路正确，可以保留。

## 四、右下斜线检查了另一条斜线的上界

访问列是 c+i-r，原版上界却检查 c-i+r<n。必须检查真正访问的列号：

```cpp
int rightCol = c + i - r;
if (rightCol >= 0 && rightCol < n) {
    valid[i][rightCol] = false;
}
```

n=4、r=1、c=2、i=3 时，右下列号为 4，但旧上界算式得到 0<4，错误放行；valid[r][4] 在旧代码中也不合法。由于 vector<bool> 常按位存储，非法列访问未必都被同样的 sanitizer 报告捕获，不能靠“没报错”判定边界正确。

## 可以保留的框架

每次递归处理一行，循环选择当前行的一列，因此不需要再禁用整行。当前 r 行只有本次选择的一个皇后，下一层直接处理 r+1。

valid 的快照复制与恢复是可用的基础实现：保存修改前的可用格子、标记当前皇后的攻击范围、递归、恢复 valid、把本层 Q 改回 .。拷贝额外开销可以之后再讨论；本轮先把终止、棋盘形状、斜线坐标和边界修正确，不直接替换整套算法。

## 对照代码随想录的棋盘检查法

用户觉得维护 valid 繁杂，指定学习 [代码随想录的 N 皇后讲解](https://programmercarl.com/algo/backtracking/0051-n-queens.html#%E6%80%9D%E8%B7%AF)。直接读取超时后，依照用户此前允许的方式在侧边栏打开，成功读取思路、回溯三部曲、C++ 实现与总结，无需重新验证登录。以下为个人对照解释和参考改写，不复制整篇文章。

两种方法搜索同一棵逐行选列的回溯树，区别在于如何判断某个位置能否放皇后。

| 环节 | 用户的 valid 标记法 | 文章的棋盘检查法 |
|---|---|---|
| 已放皇后存在哪里 | path 棋盘 | chessboard 棋盘 |
| 怎样判断当前格 | 查询提前维护的 valid[row][col] | 临时检查它与上方已放皇后是否冲突 |
| 选择后的操作 | 放 Q、复制 valid、标记攻击范围 | 只把当前格改成 Q |
| 返回后的恢复 | 恢复 valid 快照，再把 Q 改回 . | 只把本层 Q 改回 . |

用户复制 valid 的思路并非概念错误，修正坐标与边界后可以工作；它是在维护一份棋盘之外的派生状态。不能将本层标记的格子简单全部改回 true，因为某些格子可能同时被更早的皇后攻击。快照恢复避免了这种误解除。棋盘检查法不保存攻击标记，因此不需要处理这类恢复问题。

### 一次递归只负责一行

定义 backtracking(row)：前 row 行各放了一个皇后，彼此不冲突；当前第 row 行以及下面各行为空，本次调用尝试第 row 行的所有列，并枚举后续完成方式。

row 是递归深度，col 是本层循环候选。不再加一个循环枚举行，放好当前行后递归 row+1，回来撤销当前格，再尝试本行另一列。同一条递归路径每行天然只有一个皇后。row==n 时前 n 行都已合法放置，复制棋盘并 return；保存的方案不会随后续回溯改变。

### 合法性只检查上方三个方向

尝试 (row,col) 时，只可能与前面的行冲突，检查正上方同列、左上斜线、右上斜线即可。同一行由逐行递归保证只有一个皇后；下方尚未放置。isValid 判断一个候选位置，不是每次重新验证完整棋盘。

| 方向 | 起点 | 坐标推进 | 边界 |
|---|---|---|---|
| 同列 | 上方任意行、当前 col | 遍历 0..row-1 | 不进入 row |
| 左上 | (row-1,col-1) | 行减一、列减一 | 行和列均不小于 0 |
| 右上 | (row-1,col+1) | 行减一、列加一 | 行不小于 0、列小于 n |

先记方向，不死记 45/135 度名称：向上行减，向左列减，向右列加。使用有符号 int，因为上方边界会到 -1。

### 按用户局部参数风格整理的参考实现

以下是助手基于已核对文章方法整理的学习参考，不是用户已经独立写出并在力扣提交的新版本。文章用成员 result，整理版保留用户的局部 res 和引用参数风格。

```cpp
class Solution {
public:
    bool isValid(const vector<string>& board, int row, int col) {
        int n = static_cast<int>(board.size());
        // 上方同列
        for (int r = 0; r < row; ++r) {
            if (board[r][col] == 'Q') return false;
        }
        // 左上
        for (int r = row - 1, c = col - 1;
             r >= 0 && c >= 0; --r, --c) {
            if (board[r][c] == 'Q') return false;
        }
        // 右上
        for (int r = row - 1, c = col + 1;
             r >= 0 && c < n; --r, ++c) {
            if (board[r][c] == 'Q') return false;
        }
        return true;
    }

    void backtracking(vector<vector<string>>& res, vector<string>& board,
                      int row, int n) {
        if (row == n) {
            res.push_back(board);
            return;
        }
        for (int col = 0; col < n; ++col) {
            if (!isValid(board, row, col)) continue;
            board[row][col] = 'Q';
            backtracking(res, board, row + 1, n);
            board[row][col] = '.';
        }
    }

    vector<vector<string>> solveNQueens(int n) {
        vector<vector<string>> res;
        vector<string> board(n, string(n, '.'));
        backtracking(res, board, 0, n);
        return res;
    }
};
```

isValid 只读棋盘，所以使用 const 引用。n 为小整数，按值传递即可，无需 const int&。

### 用一行皇后理解检查与撤销

n=4，已放第 0 行第 1 列：

```text
.Q..
....  ← 当前处理第 1 行
....
....
```

第 1 行四个候选：col=0 因右上 (0,1) 有 Q 不合法；col=1 同列冲突；col=2 因左上 (0,1) 有 Q 不合法；col=3 三个方向都没有 Q，可以选择。接着只修改 board[1][3]='Q' 并递归第 2 行。该分支最终得到 [.Q..,...Q,Q...,..Q.]；收集并逐层返回后，各层撤销自己那一个 Q。回到第 1 行时，第 0 行的 Q 仍保留，其他行恢复为空。

记忆顺序：一层一行，循环挑列；上方三线，没有冲突才放；放下、递归下一行、撤销；行到 n，保存返回。先口述这些含义，再写终止条件、列循环和三行选择/递归/撤销，最后补 isValid，不要从整片攻击格子的修改开始写。

### 本地参考验证与复杂度口径

整理版 C++17 对 n=1..9 与独立列排列枚举/逐对斜线参考一致，仍为 1,0,0,2,10,4,40,92,352，共 501 个方案。检查无重复、辅助函数返回后棋盘恢复、同对象复用；固定第 0 行第 1 列继续搜索得到唯一方案且前缀不变。单独检查同列、左上、右上冲突与合法候选，isValid 不改棋盘。这是助手参考实现的本地验证，不替代用户力扣提交反馈，也不改变原贴版本的右下边界待修正状态。

每次合法性检查最坏 O(n)，放置/撤销一个字符 O(1)，省掉用户每次成功选择时 O(n²) 的整个 valid 复制。整理版持有一张 O(n²) 工作棋盘和 O(n) 递归栈，不计输出的辅助空间为 O(n²)。不能把文章所写 O(n) 直接当成包括工作棋盘的完整空间分析；若只谈递归栈则是 O(n)。完整总时间还需计入搜索、候选检查与每个答案 O(n²) 的复制，本轮重点先放在状态与恢复，不忽略这些实现细节后声称严格 O(n!)。

## 用户改写棋盘检查版后结果为空

用户最新版本取消 valid，增加 isValid(path,r,c)，但选择后调用的是 backtracking(res,path,r,n)。r 从入口 0 开始从未改变，因此 r==n 永远不成立，没有一次 res.push_back。

n=1 最小模拟：入口 r=0，空格可放；写 path[0][0]='Q' 后仍递归 r=0；内层检查同列包含第 0 行，发现 Q 而跳过唯一候选；内层结束返回，外层撤销 Q，最后返回空结果。它不是必然无限递归，已有 Q 会限制继续选择，但始终没有进入下一行。

n>1 时内层仍可能在第 0 行的其他列继续放 Q，破坏了原本“一层一行，每行至多一颗皇后”的前提；不能通过增加另一处收集条件补救。正确调用为：

```cpp
path[r][c] = 'Q';
backtracking(res, path, r + 1, n);
path[r][c] = '.';
```

左上检查还有独立错误，原条件如下：

```cpp
if (c - r + i >= 0 && c + r - i < (int)path.size()
    && path[i][c - r + i] == 'Q') return false;
```

实际读取左上列号 c-r+i，上界却检查右上列号 c+r-i。向上到第 i 行走了 r-i 步，因此左上列为 c-(r-i)，右上列为 c+(r-i)。检查上下界必须与实际访问的坐标一致。

例如 n=4，尝试 (r,c)=(1,3)，上方已有皇后 (0,2)。i=0 时实际左上列为 2，应该检测到冲突，但错配的上界算出 4<4 为假，跳过冲突格。此处错误主要是漏检，不同于之前 valid 右下写入导致的非法列访问。

保留用户单变量 i 算式写法时，最小修正为：

```cpp
for (int i = r; i >= 0; --i) {
    int col = c - r + i;
    if (col >= 0 && col < (int)path.size() && path[i][col] == 'Q') {
        return false;
    }
}
```

isValid 在放皇后之前调用，正常逐行递归时当前行仍为空，因此从 i=r 开始包含当前格本身不是错误，只是多一次检查。更清楚的写法是同列和两条斜线均从 r-1 开始，仅检查上方。不要把这个可读性优化误当成导致空结果的主要原因。

JavaScript 对照行为模型保留用户所有判断和循环：n=1 原版调用 2 次，n=4 原版调用 65 次，两者访问到的行号集合都只有 {0}，答案均为空；仅把递归改为 r+1，n=4 返回 3 个棋盘，其中 [Q...,..Q.,...Q,.Q..] 非法，第 1 行第 2 列与第 2 行第 3 列斜线冲突；再修正左上上界后返回 2 个合法方案。本轮证据是行为模型，不是新一轮 C++ 编译或用户力扣提交。此前助手整理参考版的 C++17 n=1..9 验证记录仍独立保留。

## 把下一行行号误传给合法性检查

用户随后修正了左上上界，但改为 isValid(path,r+1,c)，实际仍放 path[r][c] 并递归 backtracking(res,path,r,n)。下一行行号加在了错误的调用处：合法性检查针对即将放置的当前格 (r,c)，只有放置完成后的递归才推进到 r+1。

本轮完整读取报错附件，AddressSanitizer 的 heap-buffer-overflow 调用栈指向 isValid 内 path[i][c] 的同列检查，READ of size 8，经 basic_string 取内部数据指针。不是标准库需要修复，而是使用了不存在的行字符串。不能把 READ of size 8 理解成正在读取一个八字节字符。

最小反例 n=1：棋盘仅有第 0 行；backtracking 的 r=0，通过 r==n 判断后调用 isValid(path,1,0)；isValid 中局部 r=1，循环第一次 i=1，访问 path[1][0]，外层 vector 的第 1 行不存在。在尚未放置皇后时就越界。这个例子足以解释错误，不断言附件未展示的具体测试输入就是 n=1，也没有重新执行原始无检查非法访问。

保持检查、放置、递归的职责对应：

```cpp
if (!isValid(path, r, c)) continue;      // 当前格能否放置
path[r][c] = 'Q';                      // 放置在当前格
backtracking(res, path, r + 1, n);      // 下次处理下一行
path[r][c] = '.';                      // 撤销本次选择
```

两处调用都需要改。只恢复 isValid(path,r,c) 而保留递归 r，会回到上一版行号不推进、结果为空的问题；只改变递归而保留检查 r+1，依然检查错行，并可能在当前最后一行时访问第 n 行。入口给 isValid 增加越界保护只能防止非法读取，不能修复“检查下一行却放在当前行”的语义错误。

当前三段 isValid 的算式上下界已对应访问坐标，可保留；初始化 string(n,'.') 与终止条件也正确。先修正两个调用，再测试 n=1，应得到 [["Q"]]；n=4 应有两个方案。尚未收到用户最终代码/力扣通过反馈，笔记继续本地未提交。

```cpp
class Solution {
public:
    bool isValid(const vector<string>& path, int r, int c) {
        // 检查 path[r][c] 是否可以放置皇后
        for (int i = r; i >= 0; --i) {
            if (path[i][c] == 'Q') return false;
        }

        for (int i = r; i >= 0; --i) {
            if (c - r + i >= 0 && c - r + i < (int)path.size()
                && path[i][c - r + i] == 'Q') return false;
        }

        for (int i = r; i >= 0; --i) {
            if (c + r - i >= 0 && c + r - i < (int)path.size()
                && path[i][c + r - i] == 'Q') return false;
        }

        return true;
    }

    void backtracking(vector<vector<string>>& res, vector<string>& path,
                      int r, const int& n) {
        if (r == n) {
            res.push_back(path);
            return;
        }

        for (int c = 0; c < n; ++c) {
            if (!isValid(path, r, c)) continue;

            path[r][c] = 'Q';
            backtracking(res, path, r + 1, n);
            path[r][c] = '.';
        }
    }

    vector<vector<string>> solveNQueens(int n) {
        vector<vector<string>> res;
        vector<string> path(n);
        for (int i = 0; i < n; ++i) {
            path[i] = string(n, '.');
        }
        backtracking(res, path, 0, n);
        return res;
    }
};
```

### 最终版成立的前提与记忆顺序

每次 backtracking(r) 入口，前 r 行各有一颗皇后且互不冲突，当前行与下面的行为空。isValid(path,r,c) 只检查准备放置的当前格；检查成功再放 Q，递归 r+1，返回后撤销同一个格。r==n 时完整棋盘合法，保存副本并返回，不再读取第 n 行。

用户从 i=r 开始，额外检查当前格本身。由于调用检查发生在放置前，当前行为空，结果正确；不必改为 i=r-1 才能通过。const int& n 与逐行 string(n,'.') 初始化也均正确，按值传 n 和直接构造二维棋盘仅是可读性选择。

三段检查依次为同列、左上 c-(r-i)、右上 c+(r-i)，上下界与读取的列号一致。先检查、再放置：如果在放 Q 后才调用当前 isValid，它会在当前格看到自身并拒绝，顺序不能混用。

### 复杂度

候选合法性检查最坏 O(n)，每个搜索节点最多检查 n 列。有效前缀不重复使用同一列，节点数量可用 O(n!) 宽松界估计，所以包括扫描的整体时间可给宽松上界 O(n²×n!)，并有每个输出棋盘 O(n²) 的复制成本。工作棋盘 O(n²)、递归栈 O(n)，不计输出的辅助空间 O(n²)；仅递归栈为 O(n)。学习时不要混淆棋盘存储与递归栈口径。
