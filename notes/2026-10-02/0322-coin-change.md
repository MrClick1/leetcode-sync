# 322 零钱兑换

2026-10-02 用户参考官方一维 DP 写法后，明确反馈力扣提交通过。此前二维版本曾混淆行与元素、遗漏金额继承，并让不可达标记 -1 参与取最小值。保留最终代码及这些错误，方便复盘。

## 用户通过代码

```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        int n = (int)coins.size();
        vector<int> dp(amount+1, amount+1);    // 初始化为 amount+1 表示不可达，否则会影响后面的 min()

        dp[0] = 0;

        for (int i = 0; i < amount+1; ++i) {
            // i 遍历金额
            for (int j = 0; j < n; j++) {
                // j 遍历硬币
                if (i >= coins[j]) {
                    dp[i] = min(dp[i], dp[i-coins[j]] + 1);
                }
            }
        }

        return dp[amount] == amount+1 ? -1 : dp[amount];
    }
};
```

## 状态与递推

dp[i] 表示允许使用所有面额，凑出金额 i 所需的最少硬币数。枚举最后一枚硬币 coins[j]，剩余金额为 i-coins[j]，候选数量是 dp[i-coins[j]]+1。枚举所有面额后取最小值。

面额严格为正，所以剩余金额小于当前金额；金额从小到大遍历，依赖的状态已经算好。剩余金额的方案仍允许使用所有面额，因此同一硬币可以无限重复使用。无需排序 coins。

金额为 0 时需要 0 枚硬币。用户外层从 i=0 开始也是正确的：所有硬币面额都大于 0，此轮内层条件均为假，dp[0] 不变；官解从 1 开始仅省去这一轮。

## 为什么用 amount 加一表示不可达

面额至少为 1，任意可达金额 i 的最少硬币数不会超过 i，更不会超过 amount。因此 amount+1 不可能是合法答案，可以作为不可达标记。

dp[i] 初始为 amount+1，更新只会变小。若前驱不可达，候选为 amount+2，不会胜过当前值，也不会误造可达方案。题目 amount<=10000，这次加法安全；不可直接照搬成 INT_MAX+1，否则会发生有符号溢出。

最终状态只可能是合法数量或原标记 amount+1。因此用户的 ==amount+1 与官解的 >amount 判断等价。amount=0 时返回 dp[0]=0。

## 历史错误

| 写法 | 问题 | 修正方向 |
|---|---|---|
| 二维 dp[j]=j/coins[0] | dp[j] 是一行 vector，右侧是 int | 初始化单元格 dp[0][j] |
| cions[i] | 硬币变量名拼错 | coins[i] |
| dp[i][j-coins[i]] 无条件访问 | 金额不足时负下标越界 | 先判断 j>=coins[i] |
| 二维每行只从 j=coins[i] 开始且未复制上一行 | 小金额仍应能使用之前面额，但被遗留为 -1 | 每个金额先继承上一行，或先复制整行 |
| min(-1,合法数量) | -1 比合法数量小，错误淘汰可行方案 | 单独处理不可达，或使用足够大的标记 |
| -1+1 | 把不可达状态伪造为 0 枚硬币 | 不可达状态不能直接参与该运算 |

例如 coins=[2,5,10,1]，二维版本处理硬币 5、金额 5 时，会算 min(dp[1][0]+1,dp[0][5])=min(1,-1)=-1。这是局部可复现错误，不需要假定用户当时未提供的 amount 的具体值，只需 amount>=5。

## 二维与一维的区别

二维 dp[i][j] 限制使用前 i+1 种硬币，按“用不用当前面额”分类；一维 dp[i] 允许使用所有面额，按“最后一枚选什么”分类。两种定义都成立，但不能把各自 i 的含义混用。

本题统计最少数量，不统计方案个数。后续学习组合数或排列数问题时，需要重新理解循环顺序，不能直接套用本题结论。

本轮静态检查状态依赖、正面额边界、amount=0、不可达标记和返回条件，逻辑正确；通过反馈来自用户，本轮未重新编译执行。
