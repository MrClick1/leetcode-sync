# 300 最长递增子序列

2026-10-02 用户 O(n²) 动态规划和最终贪心加二分版本均明确反馈力扣通过。进阶经过多轮交流才写出，仍自评不熟练，标记为已通过、状态含义与二分边界待巩固。其他已暂停的解法仍按原安排留待首轮后复习。

## 用户通过代码

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int n = (int)nums.size();
        int res = 1;

        vector<int> dp(n, 1);

        for (int i = 1; i < n; ++i) {
            for (int j = 0; j < i; ++j) {
                if (nums[i] > nums[j]) {
                    dp[i] = max(dp[i], dp[j] + 1);
                    res = max(res, dp[i]);
                }
            }
        }

        return res;
    }
};
```

## 状态与递推

dp[i] 表示必须以 nums[i] 结尾的最长严格递增子序列长度。它不是前 i+1 个元素中任意结尾的最长长度；固定结尾才能用 nums[j] 判断能否接上 nums[i]。

每个元素自己就是长度 1 的递增子序列，所以所有 dp 初始为 1。枚举所有 j<i，保证相对顺序；只有 nums[j]<nums[i] 才能把 nums[i] 接到以 nums[j] 结尾的最优序列后面，得到 dp[j]+1，在候选中取最大值。子序列不要求连续，因此 j 不限于 i-1。

每条长度大于 1 且以 i 结尾的递增子序列，都有一个倒数第二个下标 j<i，且 nums[j]<nums[i]；循环枚举了这些候选，不漏方案。等值元素不能延长严格递增序列。

最终答案是所有 dp[i] 的最大值，因为最优序列可以结束在任意位置，不能直接返回 dp[n-1]。原代码把 res 更新放在可连接分支内仍然正确：res 初始 1，未进入分支时当前 dp[i] 也为 1，不会遗漏更大答案。

## 手算示例与边界

```text
nums = [10,9,2,5,3,7,101,18]
dp   = [ 1,1,1,2,2,3,  4, 4]
res  = 4
```

例如 nums[i]=7 时，前面的 2、5、3 都能作为前驱，分别产生长度 2、3、3，所以 dp[i]=3。结尾状态只记录长度，不要求还原具体序列。

nums=[1,2,3,0] 时 dp=[1,2,3,1]，答案为 3，最后状态却为 1；说明返回历史最大值的必要性。

nums=[7,7,7] 或严格递减时，所有状态保持 1。n=1 时循环不进入，res=1 正确。本题保证数组非空，无需强行增加空数组处理。

## 复杂度与复习

内层遍历次数为 1+2+…+(n-1)，时间 O(n²)，辅助空间 O(n)。本轮静态核对状态、递推、初始化、边界和结果收集，未重新编译运行；力扣通过来自用户反馈。

复习时先说清“以 i 结尾”，再问“前一个元素可以在哪”：下标必须小于 i，数值必须小于 nums[i]。找到候选后用 dp[j]+1 更新，并维护所有结尾中的最大值。

## 官解贪心加二分的状态

用户主动提供完整官解并请求教学。d[k] 表示在目前已处理的数组前缀中，长度恰好为 k 的严格递增子序列的最小结尾值；len 是目前可实现的最大长度。这里 k 是长度，不是原数组下标。不要说“每个长度的最长序列”，应说“所有该长度的序列中最小的结尾”。

例如 [2,5] 与 [2,3] 都长为2，但后者可接上4，前者不能。长度相同时，更小的结尾让未来可接的数更多；对后续元素只需保留最小尾值。不会因此舍弃已有的更长长度状态。

每个 d[k] 对应某条存在的子序列，但不同 k 的记录不一定来自同一条路径。整体 d 不能直接当成原数组的一条实际子序列，官解只返回长度。

## 官解示例

| 读入的数 | d[1..len] | len | 动作 |
|---|---|---:|---|
| 0 | [0] | 1 | 初始化长度1的最小结尾 |
| 8 | [0,8] | 2 | 8大于最大长度的结尾，延长 |
| 4 | [0,4] | 2 | 长度2的结尾由8降低到4 |
| 12 | [0,4,12] | 3 | 12可接在长度2的序列后 |
| 2 | [0,2,12] | 3 | 长度2的结尾降到2，已有长度3保持 |

最后 [0,2,12] 在输入 [0,8,4,12,2] 中并非合法子序列，因为2出现在12之后。此时长度2的状态有见证 [0,2]，长度3的状态有见证 [0,4,12]（还有其他同尾见证）。因此 len=3 仍然正确。

## 为什么 d 严格递增

考虑一条长度 k+1 且结尾为 d[k+1] 的递增子序列，删除最后一个元素，留下长度 k 的子序列，其结尾 x 严格小于 d[k+1]。而 d[k] 是所有长度 k 结尾的最小值，所以 d[k]<=x<d[k+1]。这保证可以对 d 二分。

## 当前数 x 的两种更新

如果 x>d[len]，已有一条长度len、结尾为d[len]的序列，且其元素都来自此前的输入，可接上当前x，得到长度len+1，更新 d[++len]=x。

否则找到第一个 d[k]>=x 的位置 k，把 d[k] 替换为 x。此前 d[k-1]<x（k=1 时直接由x组成单元素序列），所以x可以形成长度k的序列；其新结尾不大于旧值。没有 d[k]<x，所以当前数不能新形成比k更长的序列。更新仅改善一个长度的结尾，len不变。

相等时也在该位置替换，不延长；例如 [7,7,7] 的len始终是1。

## 对照官解二分

```cpp
int l = 1, r = len, pos = 0;
while (l <= r) {
    int mid = (l + r) >> 1;
    if (d[mid] < nums[i]) {
        pos = mid;
        l = mid + 1;
    } else {
        r = mid - 1;
    }
}
d[pos + 1] = nums[i];
```

这段找的是最后一个严格小于当前数的下标pos，再更新下一格；等价于替换第一个大于或等于当前数的位置。用户贴出的文字说“第一个比当前数小”与代码不符，讲解应以实际代码为准并指出应为“最后一个小于”。区间关系应为 d[k-1]<x<=d[k]，包含相等情况，不能用两侧均严格小于的描述遗漏重复数。

pos初始0表示尚未找到较小值，最终更新d[1]；代码不需要读取d[0]，所以d[0]初始化0也不会错误影响负数输入。若找到较小值则记录mid，但继续向右找，直到得到最右侧的合格位置。mid的>>1在此非负下标范围相当于除以2。

例替换 x=2、d=[0,4,12]（下标1..3）：l=1,r=3,pos=0；mid=2、d[2]=4>=2，r=1；mid=1、d[1]=0<2，pos=1,l=2；退出，更新d[2]=2。指针更新与先前学习的闭区间二分一致。

每个输入元素最多一次O(log n)二分，总时间O(n log n)，额外空间O(n)。以上是官解讲解阶段；用户后续最终进阶通过记录见下方，本轮没有重新编译运行。

## 用户最终贪心加二分通过代码

以下保留用户通过版原代码，包括尚需纠正的两条注释；实际执行逻辑已正确。

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int n = (int)nums.size();

        vector<int> d(n+1, 0);      // d 子子序列，并且每个元素都是长度为 i+1 的子序列的最小值
        int len = 1;
        d[len] = nums[0];

        for (int i = 1; i < (int)nums.size(); ++i) {
            if (nums[i] > d[len]) {
                d[++len] = nums[i];
            }else {
                // 查找第一个大于等于 nums[i] 的数，进行更新
                int l = 1;
                int r = len;
                int first = len;

                while (l <= r) {
                    int mid = l + (r - l) / 2;
                    if (d[mid] >= nums[i]) {
                        first = mid;
                        // 继续往左边找
                        r = mid - 1;
                    }else {
                        // nums[mid] <= nums[i] 往右边找
                        l = mid + 1;
                    }
                }
                d[first] = nums[i];
            }
        }
        return len;
    }
};
```

两条注释应分别改成“d[k]为长度k的严格递增子序列最小结尾值”和“d[mid]<nums[i]，往右边找”。d不是一条完整实际子序列，最小值指结尾，不是序列的最小元素。此处使用1起始下标，不能把k写成k+1。

first=len是安全的：进入else已知x<=d[len]，len一定是候选。正确二分会继续找更靠左的候选；不能把此初始化当作错误二分的补救。

## 与官方二分的区别

| 对比点 | 用户版 | 官方版 |
|---|---|---|
| 查找目标 | 第一个大于或等于x的位置first | 最后一个严格小于x的位置pos |
| 记录候选并继续找 | d[mid]>=x：first=mid，向左 | d[mid]<x：pos=mid，向右 |
| 无候选的初始含义 | first=len，是已保证的合格位置 | pos=0，表示未找到更小尾值 |
| 更新 | d[first]=x | d[pos+1]=x |

两者落在同一条分界线上：first=pos+1，效果完全等价。无需改回官方写法。用户的mid=l+(r-l)/2与官解的(l+r)>>1在本题非负小下标范围给出相同中点；用户版保留差值写法即可。两者复杂度相同，O(n log n)时间、O(n)空间。

| 问题 | 原因或最小反例 | 修正 |

| mid在while外 | [1,2,1]进入二分后l=1仍重复使用mid=0，区间不再缩小而死循环 | 每轮按当前l/r重算mid |
