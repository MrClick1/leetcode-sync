# 152 乘积最大子数组

2026-10-02 用户修正最大值转移和答案初始化后反馈力扣通过。本题使用双数组 DP：同时保留以当前位置结尾的最大、最小乘积，应对负数使大小关系翻转。已通过，状态含义与独立重写仍需复习；不把通过等同于熟练掌握。

## 用户通过代码

```cpp
class Solution {
public:
    int maxProduct(vector<int>& nums) {
        int n = (int)nums.size();
        int res = nums[0];

        vector<int> minMul(n);
        vector<int> maxMul(n);

        for (int i = 0; i < n; ++i) {
            minMul[i] = nums[i];
            maxMul[i] = nums[i];
        }

        for (int i = 1; i < n; ++i) {
            minMul[i] = min({minMul[i], minMul[i-1] * nums[i], maxMul[i-1] * nums[i]});
            maxMul[i] = max({maxMul[i], minMul[i-1] * nums[i], maxMul[i-1] * nums[i]});
            res = max({res, minMul[i], maxMul[i]});
        }

        return res;
    }
};
```

## 状态与三个候选

maxMul[i] 表示必须以 nums[i] 结尾的非空连续子数组的最大乘积；minMul[i] 是同样条件下的最小乘积。res 才表示所有已处理位置中的最大乘积。

必须以 i 结尾的子数组，要么只含 nums[i]，要么在以 i-1 结尾的子数组后接上 nums[i]。不能接任意更早的历史最优结果，否则可能不连续。乘正数保持大小关系，乘负数反转大小关系，乘零都变成零，因此只需比较三个候选：

```cpp
nums[i]                         // 当前元素独立成段
maxMul[i - 1] * nums[i]          // 延续之前的最大乘积
minMul[i - 1] * nums[i]          // 延续之前的最小乘积
```

分别取 max、min，即得到当前位置的两种状态。不需要枚举所有子数组，也不需要为零单独写分支。

例如 [-2,3,-4]：

| i | 当前值 | 单独、接之前最小、接之前最大 | minMul[i] | maxMul[i] | res |
|---|---:|---|---:|---:|---:|
| 0 | -2 | 初始化 | -2 | -2 | -2 |
| 1 | 3 | 3、-6、-6 | -6 | 3 | 3 |
| 2 | -4 | -4、24、-12 | -12 | 24 | 24 |

以 3 结尾时最小乘积 -6 来自 [-2,3]，乘上下一个 -4 后变为 24。这就是最小值也必须留下来的原因。

## 首版错误与修正

首版 maxMul 转移把 maxMul[i-1]*nums[i] 写了两次，漏掉 minMul[i-1]*nums[i]。即使修好 res，这仍会漏掉上例的 24。两种状态应使用相同的三个候选，只是分别取 min 和 max。

首版 int res 未初始化，随后读取它参与 max 属于未定义行为；它不会自动等于零。应初始化为 nums[0]，同时覆盖循环从 1 开始而未处理的首元素，以及只有一个元素的输入。不能无条件初始化为零，例如 [-2] 的答案应为 -2，题目不允许空子数组。

最终代码已经修正这两处，不能继续把历史问题当作当前代码错误。

## 与用户贴出官解的对照

参考：[力扣官方题解](https://leetcode.cn/problems/maximum-product-subarray/solutions/250015/cheng-ji-zui-da-zi-shu-zu-by-leetcode-solution/)。本次分析依据用户贴出的代码和题目约束，没有另行读取网页。

| 比较点 | 用户代码 | 官解代码 | 理解 |
|---|---|---|---|
| 初始化 | 循环把 nums[i] 赋给两个数组 | vector<long>(nums.begin(), nums.end()) | 都复制每个元素的值作为单独成段候选；不是引用原数组 |
| 递推写法 | min/max 的花括号三元素版本 | 嵌套 min/max | 比较相同的三个候选，含义相同 |
| 当前元素候选 | 使用预先初始化的 minMul[i]/maxMul[i] | 显式写 nums[i] 并转换为 long | 用户当前项在被更新前就是 nums[i]，正确 |
| 更新顺序 | 先 minMul[i]，再 maxMul[i] | 先 maxF[i]，再 minF[i] | 都只依赖 i-1，顺序不影响结果 |
| 全局答案 | 遍历中更新 res | 最后扫描 maxF 取最大值 | 两种统计方式等价 |
| 数值范围 | int 数组 | long 数组与极小负积处理 | 需结合题目约束及平台理解，见下节 |

用户 res=max({res,minMul[i],maxMul[i]}) 正确，但 minMul[i] 不会超过 maxMul[i]，可以简化为：

```cpp
res = max(res, maxMul[i]);
```

官解最后的 *max_element(maxF.begin(),maxF.end()) 可以拆成两步：

```cpp
auto it = max_element(maxF.begin(), maxF.end());
return *it;
```

max_element 在 [begin,end) 内找到最大元素，返回指向它的迭代器；一元 * 解引用，取出该位置的元素。例 maxF=[2,6,-12,4]，it 指向下标 1 的 6，*it 为 6。it 本身不是整数下标；vector 中 it-maxF.begin() 才得到下标。end 指向最后一个元素之后，空区间会返回 end，不能对它使用 *；本题保证数组非空，所以可以直接取值。

算法不要求先排序，也不会修改 maxF；最后再扫描一次仍是 O(n) 时间，和逐步更新 res 等价。完整语法、min_element 对照、重复最大值与空区间规则见 [C++ 语法笔记的极值查找](../01-cpp语法知识文档.md#26-max_element-与-min_element-找极值元素)。

## long 与极小负积保护

用户贴出的题目明确保证任何子数组乘积都在 32 位整数范围内。两种 DP 状态及递推的候选都对应真实子数组乘积，因此 int 足够；官解中的 minF[i]<INT_MIN 在这个约束下不会触发。INT_MIN 表示 int 可表示的最小值，32 位 int 下为 -2147483648。

官解还写了以下额外处理，它不是基本递推的一部分：

```cpp
if (minF[i] < INT_MIN) {
    minF[i] = nums[i];
}
```

如果只有最终最大答案保证在 int 范围内，中间的最小负积可能超出范围。这类保护先用更宽类型计算，再丢弃过小的负积；丢弃后 minF[i] 不能再被称为数学上严格的最小乘积。在最终答案仍保证为 int、元素为整数的前提下，这个极小负积在遇到零之前若再乘负数，会形成超出 INT_MAX 的正积，违反前提；乘正整数不能使它成为更有利的候选，乘零则重置。因此可以不再保留它来求最大答案。此解释是针对代码的推导，不断言官方加这段代码的历史原因。

long 不保证跨平台都是 64 位：常见 64 位 Linux 为 64 位，而 Windows/MSVC 中仍是 32 位。若代码依赖更宽整数计算，应明确使用 long long，并确保乘法本身未溢出；乘法溢出后再执行 if 无法补救。当前题目保证下无需为了照抄官解而改类型或增加截断。

## 独立重写的记忆方法

先口述：连续就接前一个位置；乘负数会翻转，所以最大最小一起留；当前元素可以重新开始；答案取历史最大。

写代码时依次回答：

1. 状态是否明确为必须以 i 结尾，而不是整个前缀的答案？
2. 三个候选是否分别为 nums[i]、前一个最大乘当前、前一个最小乘当前？
3. 最初的最大、最小和全局答案是否都包含 nums[0]？
4. 最后返回的是历史最大，而不是 maxMul[n-1] 吗？例如 [2,3,-2,4] 最后状态是 4，但答案是此前的 6。

复习时先用 [-2,3,-4] 解释最小状态的用途，再用 [-2,0,-1] 验证不能跨过零拼成不连续的 [-2,-1]，最后检查单元素 [-2] 的初始化。暂不扩展滚动变量等其他写法，先把双数组状态写熟。
