## 用户通过版本

```cpp
class Solution {
public:
    int jump(vector<int>& nums) {
        int n = (int)nums.size();
        int curMaxLeap = 0;
        int nextMaxLeap = 0;
        int cnt = 0;

        for (int i = 0; i < n; ++i) {
            nextMaxLeap = max(nextMaxLeap, i + nums[i]);
            if (curMaxLeap >= n - 1) break;

            if (i == curMaxLeap) {
                ++cnt;
                curMaxLeap = nextMaxLeap;
            }
        }

        return cnt;
    }
};
```

## 从第 55 题的覆盖范围到最少次数

55 只判断能否到达，可以持续更新一个全局最远范围。45 还要区分扩大范围用了几次跳跃，因此把位置按最少跳跃次数分层：0 次只能位于下标 0；1 次能覆盖第一段位置；遍历这段位置的所有起跳选择，再得到 2 次能覆盖的范围，以此类推。

这里 i 是枚举候选起跳点的扫描指针，不是实际角色所在的位置。curMaxLeap 是 cnt 次跳跃最多能覆盖的右边界，也不是某次必须落到的地点。不能理解成角色每次都跳到右边界。

## 三个状态的准确含义

- cnt：当前覆盖范围对应的跳跃次数。
- curMaxLeap：使用至多 cnt 次跳跃可覆盖的最远下标；在扫描一层时固定不变。
- nextMaxLeap：利用当前已经扫描过的可达起跳点，多跳一次可达到的最远候选。在本层扫描结束前，它还不一定是完整下一层的右边界。

当 i<curMaxLeap 时，本层还有候选起跳点没检查，继续累计 nextMaxLeap，不增加次数。当 i==curMaxLeap 时，本层所有新位置均已检查，下一层最远范围确定，才执行 ++cnt 和 curMaxLeap=nextMaxLeap。

不重置 nextMaxLeap 也正确：它保存的是非递减候选最大值；上一层的信息已经包含在当前边界中，保留它不会虚构更远范围，后面只需继续取 max。

## 示例模拟：[2,3,1,1,4]

0 次跳跃仅在下标 0。扫描下标 0，下一层候选为 0+2=2；本层结束，cnt=1、curMaxLeap=2。一跳可以落在 1 或 2，不是强制落在 2。

接着扫描一跳内可达的候选下标 1、2：

- 从下标 1 再跳，可到 1+3=4，nextMaxLeap 更新为 4。
- 从下标 2 再跳，只能到 2+1=3，nextMaxLeap 仍为 4。
- 扫描到本层右边界 2，统一增加一次，cnt=2、curMaxLeap=4。

两次已覆盖终点，答案为 2。具体可选路径是 0→1→4，但程序只求次数，不保存或逐步执行路径。扫描到下标 2 不表示角色实际走了 0→1→2。

| 执行位置 | i | cnt | curMaxLeap | nextMaxLeap |
|---|---:|---:|---:|---:|
| 初始化 | — | 0 | 0 | 0 |
| 扫描下标 0 | 0 | 0 | 0 | 2 |
| 第 0 层结束，扩展到下一层 | 0 | 1 | 2 | 2 |
| 扫描下标 1，不到当前边界 | 1 | 1 | 2 | 4 |
| 扫描下标 2 | 2 | 1 | 2 | 4 |
| 第 1 层结束，扩展到下一层 | 2 | 2 | 4 | 4 |
| 下次循环检查到已覆盖终点，结束 | 3 | 2 | 4 | 4 |

用户的成功检查在每轮更新 nextMaxLeap 后，所以会在下一轮才 break。这多做一次不影响答案；并不是必须再跳一次才能确认成功。

## 为什么次数一定最少

每层考虑同样跳跃次数内所有可达的候选位置。只要当前 cnt 次的右边界尚未覆盖终点，就不可能用 cnt 次到达；需要扩展下一层，次数加一。第一次覆盖到终点的层数，就是最少次数。

贪心保留的是整层候选能够形成的最远覆盖范围，不是挑 nums[i] 最大的落点，也不是每次跳尽当前位置允许的步数。后两种直觉会遗漏更优路线。

## 边界与可选整理

- [0]：起点就是终点，第一次成功检查就 break，cnt=0。
- [1,1,1,1]：每一层只能扩展一个下标，答案为 3。
- [2,3,0,1,4]：可以从下标 1 跳到末尾，答案为 2；出现 0 不影响已有可选路线。
- 题目保证可达，所以不用额外处理当前层无法扩大而停滞的情况；不要把代码直接当作一般不可达数组的最少次数接口。
- 如果去掉用户代码中的成功检查，又遍历到 n-1，就可能在终点把次数多加一次。

常见整理版仅遍历到 n-2，终点无需作为起跳候选，也就不必保留原成功检查：

```cpp
int jump(vector<int>& nums) {
    int n = (int)nums.size();
    int end = 0, farthest = 0, steps = 0;
    for (int i = 0; i < n - 1; ++i) {
        farthest = max(farthest, i + nums[i]);
        if (i == end) {
            ++steps;
            end = farthest;
        }
    }
    return steps;
}
```

用户原版正确，无需为了采用这一整理版而修改。上述案例是逻辑复核，不是本轮本地 C++ 测试输出。

## 复杂度与复习重点

每个下标最多扫描一次，时间 O(n)，额外空间 O(1)。先分别说清“扫描位置 i”“当前层边界”“下一层候选边界”，再说明为什么只在扫描完一层时计数。通过不代表已熟练，后续可重新模拟并独立写出两个边界。
