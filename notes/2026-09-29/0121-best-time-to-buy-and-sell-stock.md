# 121. 买卖股票的最佳时机

状态：2026-09-29 用户确认 LeetCode 提交通过，代码审阅正确。当前为一次遍历、维护历史最低买入价与最大利润的贪心版本。遵循网页端学习方式，本轮未创建本地脚手架或另行编译测试。

## 用户通过版本

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int n = (int)prices.size();
        int minPrice = prices[0];
        int res = 0;

        for (int i = 0; i < n; ++i) {
            res = max(res, prices[i] - minPrice);
            minPrice = min(minPrice, prices[i]);
        }

        return res;
    }
};
```

## 从卖出日推导思路

固定今天为卖出日：利润 = 今天价格 - 买入价格。在今天之前所有可能的买入日里，价格最低的那天一定不会比其他选择差。因此不必枚举所有买入日，只需记住此前最低价。

遍历所有卖出日，取这些利润的最大值。合法交易必须先买后卖，只能进行一次买入与卖出；不能为了找到最大最小值而排序，排序会丢失日期顺序。

记忆：每天尝试卖出，搭配此前最低买入价，记录历史最大利润。

## 两个变量与更新顺序

- minPrice：对 i>=1，在计算当天利润之前，保存 prices[0...i-1] 的最小值。
- res：保存此前所有合法单次交易的最大利润，并与不交易的利润 0 比较。
- 先计算 prices[i]-minPrice：使用此前的买入价，保证买入日在卖出日之前。
- 再更新 minPrice：今天可以成为后面某天的买入日。
- 最终返回 res，而不是最后一天的利润；最优卖出日可能不是最后一天。

用户从 i=0 开始，也正确。首轮计算 prices[0]-prices[0]=0，只是重复初始化的效果，不表示真的进行同日买卖，不会产生正利润。可选择从 i=1 开始，少做一次无效比较，使此前最低价的语义从首轮就严格成立；无需为正确性改写。

res 初始为 0，表示可以不交易。价格持续下降时不会被负利润更新；只有一天时也返回 0。题目保证数组非空，初始化 prices[0] 合法。

## 示例模拟

prices = [7,1,5,3,6,4]，保留用户 i=0 的写法：

| 下标 i | 当天价格 | 计算前 minPrice | 当天计算的利润 | 更新后 res | 更新后 minPrice |
|---|---:|---:|---:|---:|---:|
| 0 | 7 | 7（初始化） | 0（初始化效果） | 0 | 7 |
| 1 | 1 | 7 | -6 | 0 | 1 |
| 2 | 5 | 1 | 4 | 4 | 1 |
| 3 | 3 | 1 | 2 | 4 | 1 |
| 4 | 6 | 1 | 5 | 5 | 1 |
| 5 | 4 | 1 | 3 | 5 | 1 |

最终利润为 5，买入价格为 1，卖出价格为 6。最后一天利润只有 3，不能覆盖历史答案 5。

## 正确性与易错点

对于任意卖出日 i，所有买入日 j<i 中，最小 prices[j] 给出的利润最大。扫描时维护了这个最小值，又检查了每一个卖出日，所以不会遗漏全局最优。若所有交易都亏损，保留不交易的 0。

- 不能直接用整个数组的最大值减最小值：例如 [5,1]，最大价在最低价之前，不能获得 4，答案为 0。
- 不需要记录所有价格或排序，一次扫描维护两个整数即可。
- res 记录历史最优；minPrice 记录买入候选，二者含义不同，更新不能混淆。
- [7,6,4,3,1]、[3]、[2,2,2] 都返回 0；[0,4] 返回 4。
- 本题仅一次交易，不能套用累加每天上涨利润的多次交易方法。

上述案例为逻辑复核，不是本轮本地执行测试结果。

## 复杂度

遍历 n 个价格，每次常数次比较，时间 O(n)。只使用 minPrice、res 与循环变量，额外空间 O(1)。
