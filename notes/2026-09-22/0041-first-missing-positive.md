# 41. 缺失的第一个正数（二刷）

状态：2026-09-22 用户确认 LeetCode 提交通过，代码复核正确。初刷笔记见 [2026-08-29](../2026-08-29/0041-first-missing-positive.md)。

## 核心思路

长度为 n 的数组，答案一定在 [1,n+1]：若 1 到 n 全部出现，则答案为 n+1；否则答案是其中最小的缺失值。

用输入数组本身记录出现情况：数字 x（1 <= x <= n）应放到下标 x-1。把当前数字送到自己的位置后，继续检查交换过来的新数字。最后从左到右查找第一个 nums[i] != i+1 的位置。

## 通过的解法

保持用户代码逻辑，仅修正注释中将数字与下标混淆的表述，并整理格式。

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        int n = (int)nums.size();

        for (int i = 0; i < n; ++i) {
            // 数字 x 应放到下标 x - 1
            // 每次交换后都重新检查 nums[i] 是否在合法范围内
            while (nums[i] <= n && nums[i] >= 1 &&
                   nums[i] != nums[nums[i] - 1]) {
                swap(nums[i], nums[nums[i] - 1]);
            }
        }

        for (int i = 0; i < n; ++i) {
            if (nums[i] != i + 1) return i + 1;
        }
        return n + 1;
    }
};
```

## 二刷错误复盘

### 1. 范围检查放在外层 if，交换后越界

```cpp
if (nums[i] >= 1 && nums[i] <= n) {
    while (nums[i] != nums[nums[i] - 1]) {
        swap(nums[i], nums[nums[i] - 1]);
    }
}
```

以 [3,4,-1,1] 为例：i=0 时数字 3 合法，交换后数组变为 [-1,4,3,1]，下一轮条件会访问 nums[-2]。外层 if 不会自动重新执行。

修复：把范围检查放进 while。循环中改变的值，其合法性需要每轮重新检查。

### 2. 范围判断必须在二次下标访问之前

&& 从左向右短路判断。两个范围判断的先后可以互换，但都必须在 nums[nums[i]-1] 之前，这也避免了极端负数参与减一计算。

第三个条件防止重复数字死循环。例如 [1,1] 中，下标 1 的数字 1 想去下标 0，但那里已经是 1；再交换不会改变任何状态，因此应停止。

### 3. 多余的大括号使函数提前结束

第二个 for 报 expected member name，并不一定是这个 for 自身写错。此前多余的 } 提前关闭了函数，编译器认为 for 出现在类内、函数外。通过缩进核对 while、for、函数和类的括号配对。

### 4. 注释区分数值和下标

应写“数字 x 放在下标 x-1”，不能写成“i 放在 i-1”，因为 i 是正在检查的位置，不是需要归位的数值。

## 为什么嵌套循环仍是 O(n)

每次有效交换都让目标下标 x-1 新增一个正确就位的数字 x。已就位的位置不会被后续交换破坏：其他相同数字试图进入它时，会被第三个条件拦住。因此全部交换至多 n 次，加上两次线性扫描，总时间 O(n)。

只使用下标、长度等常数个变量，额外空间 O(1)，会修改输入数组。

## 与其他方案比较

- 排序后扫描：O(n log n) 时间，不满足线性要求。
- unordered_set：单次查询平均 O(1)、最坏 O(n)，建表后查找的整体平均时间 O(n)，但额外空间 O(n)，不满足空间要求。
- 当前原地归位：O(n) 时间、O(1) 额外空间。
