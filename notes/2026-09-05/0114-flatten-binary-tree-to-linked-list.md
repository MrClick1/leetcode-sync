# 114. 二叉树展开为链表

## 题目要求

- 使用原来的 `TreeNode` 节点调整连接关系。
- 展开后所有节点的 `left` 为 `nullptr`，`right` 指向下一个节点。
- 节点顺序与原树的先序遍历一致：根 → 左子树 → 右子树。
- 节点数为 `[0, 2000]`；进阶要求 `O(1)` 额外空间。

## 示例

输入：`[1,2,5,3,4,null,6]`。

展开后的右指针链：`1 -> 2 -> 3 -> 4 -> 5 -> 6 -> nullptr`，所有左指针为空。

## 进阶：原地迭代，时间 O(n)、额外空间 O(1)

从当前节点 `cur` 出发，如果存在左子树：先从 `cur->left` 沿 `right` 找到最右节点 `pre`，把原右子树接到 `pre->right`；再让 `cur->right` 指向原左子树，并清空 `cur->left`。然后移动到 `cur->right` 继续处理。

```cpp
class Solution {
public:
    void flatten(TreeNode* root) {
        TreeNode* cur = root;
        while (cur != nullptr) {
            if (cur->left != nullptr) {
                TreeNode* pre = cur->left;
                while (pre->right != nullptr) {
                    pre = pre->right;
                }

                pre->right = cur->right;
                cur->right = cur->left;
                cur->left = nullptr;
            }
            cur = cur->right;
        }
    }
};
```

三条连接语句的顺序很重要：先接住原右子树，再覆盖 `cur->right`，最后清空左指针，防止丢失子树。

此处 `pre` 是尚未展开的左子树沿右指针到达的最右节点，不一定是左子树先序遍历的最后一个节点。例如左子树只有一条左链时，`pre` 就是左子树根节点。之所以仍正确，是因为把原右子树放到 `pre` 的右侧后，先序遍历会先访问 `pre` 的整个左子树，之后才进入接上的原右子树。后续循环也会继续处理这些左孩子。因此每次调整都保持先序节点顺序。

时间复杂度 `O(n)`：外层每个节点处理一次；内层查找沿左子树的右边界走，不是重复扫描已展开链的尾部。不同轮次的这类右边界扫描不会重复走同一条原树右边；新接上的右边只用于串联后续部分，不会被后续左子树内部的查找反复扫描。因此累计查找也是 `O(n)`。

额外空间 `O(1)`：仅使用 `cur`、`pre`，不使用递归栈或额外容器。用户已按此结构实现，静态 review 未发现逻辑问题，并已确认 LeetCode 提交通过。

## 基础递归版本 review

用户增加了 `if (node == nullptr) ... else ...`：没有左链时连接右链，有左链时找到尾节点接上右链，再让根节点指向左链。两分支互斥，因此空分支后无需额外 `return`，也不会进入非空分支访问空指针。

递归返回时，两棵子树都已展开；当前节点最终形成“根 → 左链 → 右链”，且 `left` 已清空。空树、叶子节点、只有左子树、只有右子树均有对应处理。提前清空 `root->left` 是安全的，因为 `ltemp` 已经保存原左子树入口。

建议把“先序遍历，中左右”注释改为“递归展开左右子树，再按根、左、右连接”，并删除已注释掉的旧赋值。最终链表是先序顺序，但拼接发生在两个递归调用返回之后。

最坏时间 `O(n^2)`：对于只有左孩子的长链，寻找尾节点会反复走过长度约为 `1, 2, ..., n - 1` 的链。递归栈空间 `O(h)`，最坏 `O(n)`；尚未满足进阶 `O(1)` 额外空间。用户已确认该递归版本通过 LeetCode。

## 第一版 review：递归中的死循环与断链

用户在 `traversal(root)` 内使用 `while (root != nullptr)`，循环中保存左右子树、将左子树移到右侧，然后递归调用 `traversal(ltemp)` 和 `traversal(rtemp)`。

### 超时的直接原因

循环内从未修改当前调用的 `root` 指针。即使 `root` 是叶子节点，两个空子树的递归调用返回后，`root` 仍指向同一个叶子节点，下一轮继续执行，形成无限循环。

`root->left = nullptr` 修改的是节点成员，不会把 `root` 本身变为 `nullptr`。`TreeNode* root` 按值传递，各次递归有各自的指针变量。

递归处理单个节点时，可以先写 `if (root == nullptr) return;`，然后处理该节点并递归处理子树，无需用这个 `while` 反复处理同一节点。但仅修改循环不能修复下面的断链问题。

### 右子树没有接回结果

执行 `root->right = ltemp` 会覆盖原右子树的入口。保存 `rtemp` 可以临时保留访问入口，但 `traversal(rtemp)` 只处理右子树，不会自动把它连接到左子树展开后的尾节点。

例如根节点为 1，左孩子为 2，右孩子为 3：即使把 `while` 改成单次处理，结果也只有 `1 -> 2`，节点 3 没有接回来。若没有左子树，直接把 `root->right` 设为 `ltemp`（空指针）还会切断整个原右子树。

需要保证的连接关系是：根节点 → 左子树展开后的链 → 右子树展开后的链。递归完成子树处理与把两段链表接起来是两项不同的工作。

## 易错点：没有左子树时访问空指针

`TreeNode* node = ltemp;` 后直接判断 `node->right`，会在 `ltemp == nullptr` 时触发空指针成员访问。每个叶子节点都没有左子树，因此普通非空树也会遇到此问题。

入口的 `if (root == nullptr) return;` 只保证当前根节点非空，不保证它的左右孩子非空。在递归处理左右子树之后、查找左链尾节点之前，应增加：

```cpp
if (ltemp == nullptr) {
    root->right = rtemp;
    return;
}
```

没有左链时直接连接已经展开的右链。有左链时才执行找尾节点和拼接。仅把循环条件改为 `node != nullptr && node->right != nullptr` 不够，因为循环后仍会执行 `node->right = rtemp`，且最后的 `root->right = ltemp` 会切断原右链。

用户将 `root->left = nullptr` 放在递归前是可行的，因为已经用 `ltemp` 保存了原左子树入口。当前实现实际先递归处理子树再拼接，注释可以改为“展开左右子树，再按根、左、右连接”，以区别处理顺序与结果顺序。

## 基础递归参考代码与作用域问题

- 已用 `if (root == nullptr) return;` 替换无限循环。
- 多余的 `if (root)` 没有大括号，只控制紧接着的 `TreeNode* ltemp = root->left;` 声明；该变量的作用域局限于此子语句，后续使用 `ltemp` 会编译失败，应删掉这个多余判断。
- 先保存原左右子树，再分别递归展开，最后连接：根 → 左链 → 右链。连接时沿左链的 `right` 找到尾节点，让它指向右链。

```cpp
void traversal(TreeNode* root) {
    if (root == nullptr) return;

    TreeNode* ltemp = root->left;
    TreeNode* rtemp = root->right;

    traversal(ltemp);
    traversal(rtemp);

    root->left = nullptr;
    if (ltemp == nullptr) {
        root->right = rtemp;
        return;
    }

    root->right = ltemp;
    TreeNode* tail = ltemp;
    while (tail->right != nullptr) {
        tail = tail->right;
    }
    tail->right = rtemp;
}
```

这是帮助理解连接过程的基础递归版本：返回前保证当前子树已经展开。虽然递归先处理子树再拼接，最终结果仍是先序顺序，并不要求实际修改指针的过程也按先序执行。

在 `flatten(TreeNode* root)` 中调用 `traversal(root)` 即可。该参考写法与用户通过的 `if/else` 拼接写法等价。

复杂度：反复扫描左链尾部，最坏时间 `O(n^2)`（例如原树是一条向左的长链）；递归栈空间 `O(h)`，最坏 `O(n)`。此版本不满足进阶 `O(1)` 额外空间要求；本题最终采用前文的原地迭代版本。
