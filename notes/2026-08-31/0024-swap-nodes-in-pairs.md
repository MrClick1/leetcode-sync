# 24. 两两交换链表中的节点 —— 复盘笔记

状态：✅ 已解决

## 遇到的问题

第一版代码运行后没有结果，原因不是循环条件，而是链表已经被错误地连接成环：`first` 和 `second` 指向了同一个节点，执行 `second->next = first` 后形成了节点指向自己的自环。

修正 `second = first->next` 后，还必须在每组交换完成后执行 `pre = first`。因为交换后的 `first` 位于这一组末尾，它正是下一组前面的节点；如果不推进 `pre`，循环会反复处理同一对节点。

## 解题要点

- 使用栈上的虚拟头节点统一处理第一对节点，避免单独修改头指针。
- 每轮令 `pre` 指向待交换节点对之前的节点。
- `first = pre->next`，`second = first->next`。
- 交换前结构是 `pre -> first -> second -> nextPair`。
- 依次重连为 `first->next = second->next`、`second->next = first`、`pre->next = second`。
- 交换后结构变为 `pre -> second -> first -> nextPair`，因此令 `pre = first`。
- 循环条件必须同时保证第一个和第二个节点存在；奇数长度链表最后一个节点保持原位。
- 只修改 `next` 指针，不修改节点内部的 `val`。

## 虚拟头节点

虚拟头节点使用栈对象：

```cpp
ListNode dummy(0, head);
ListNode* pre = &dummy;
```

这样函数结束时会自动销毁虚拟节点，不需要 `new`，也不会产生额外的节点泄漏。

## 复杂度

- 每个节点只处理一次，时间复杂度 O(n)。
- 只使用固定数量的指针，额外空间复杂度 O(1)。

## 验证

- 固定测试全部通过，覆盖空链表、单双节点、奇偶长度、重复值、边界值和 100 个节点。
- 测试会检查输出节点的指针身份，确保是真实交换节点而不是修改节点值。
- 5000 组随机链表验证全部通过，同时检查交换顺序、节点值不变以及链表无环。
