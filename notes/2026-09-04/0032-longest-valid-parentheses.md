# 32. 最长有效括号

## 完成情况

- 解法：下标栈 + 连续子串边界
- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`
- 验证：25 个普通固定用例、6 个长度边界用例、10000 组随机暴力对拍均通过

## 核心思路

题目要求的是最长的**连续有效子串**。因此，除了判断括号能否匹配，还必须知道匹配完成后，这一段连续区间从哪里开始。

栈中保存的是下标，而不是括号字符：

- `-1` 表示字符串开始前的虚拟边界。
- 左括号的下标表示尚未匹配的位置。
- 未匹配右括号的下标表示有效子串不能跨越的边界。

遇到左括号时，把下标入栈。遇到右括号时，如果栈顶是左括号，就弹出它；弹出后，当前有效区间的长度是：

```cpp
i - stk.top()
```

例如 `"(()"` 中最后一个右括号匹配下标 `1` 的左括号后，栈顶是下标 `0`，所以有效长度是 `2 - 0 = 2`。

## 当前写法为什么正确

当前实现遇到无法匹配的右括号时，会把它直接压栈。因此栈中可能保留多个未匹配右括号下标。

这些右括号都是不能跨越的边界，但计算长度时只需要最近的边界。最近的边界总在栈顶，较早的边界位于它下面，不会影响 `i - stk.top()`，所以结果仍然正确。

这种写法可以通过全部测试，但栈中保留了一些不再需要的旧边界。面试和默写时，更推荐下面的标准模板。

## 更常见的标准模板

```cpp
int longestValidParentheses(string s) {
    int result = 0;
    stack<int> stk;
    stk.push(-1);

    for (int i = 0; i < static_cast<int>(s.size()); ++i) {
        if (s[i] == '(') {
            stk.push(i);
        } else {
            stk.pop();

            if (stk.empty()) {
                stk.push(i);
            } else {
                result = max(result, i - stk.top());
            }
        }
    }

    return result;
}
```

这份模板中的栈有一个清楚的不变量：栈底是最近一个未匹配右括号形成的边界，其上是尚未匹配的左括号下标。

遇到右括号时：

1. 先弹出一个下标，尝试匹配左括号。
2. 如果弹出后栈为空，说明当前右括号无法匹配，把当前下标作为新边界。
3. 如果栈不为空，说明形成了有效后缀，长度为 `i - stk.top()`。

## 本次遇到的问题

### 1. 用 `stack<char>` 保存下标

循环下标是 `int`，放入 `stack<char>` 会被转换成字符类型。较大的下标会截断，而且栈中数据的语义也变得不清楚。需要写成：

```cpp
stack<int> stk;
```

### 2. 把虚拟边界 `-1` 当作字符串下标

`-1` 只用于长度计算，不能访问 `s[-1]`。`string::operator[]` 接收无符号下标，`-1` 会被转换成一个非常大的正数，从而造成越界。

当前写法在访问 `s[stk.top()]` 前先判断：

```cpp
if (stk.top() == -1) {
    // 不能访问 s[stk.top()]
}
```

标准模板则不读取栈顶对应的字符，直接利用栈是否为空区分“成功匹配”和“形成新边界”，更不容易写出越界访问。

## 复习重点

- 栈中保存的是**下标**，因为最终需要计算连续区间长度。
- `-1` 是虚拟边界，只参与减法，不是合法字符串下标。
- 无法匹配的右括号会截断连续有效区间，必须更新边界。
- 写栈算法前先说清楚“栈中每个元素代表什么”，再决定何时入栈、出栈。
