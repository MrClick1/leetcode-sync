# 128. 最长连续序列

状态：✅ 已解决（2026-09-06，去重集合解法通过 LeetCode）

## 题目要求

给定未排序整数数组 `nums`，找出数字连续的最长序列长度。序列元素不要求在原数组中相邻，数组可能包含重复值，要求平均时间复杂度为 `O(n)`。

## 解法：`unordered_set` + 只从序列起点扩展

先把所有数字放入 `unordered_set`：

- 自动去重
- 平均 `O(1)` 判断某个数字是否存在

对集合中的每个数字 `num`，只有当集合中不存在 `num - 1` 时，才把它当作连续序列的起点。随后不断检查 `num + 1`、`num + 2` 等后继数字，并更新最大长度。

```cpp
class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        int best = 0;
        unordered_set<int> uset;

        for (int num : nums) {
            uset.insert(num);
        }

        for (const auto& num : uset) {
            // 存在前驱，说明 num 不是这段序列的起点
            if (uset.find(num - 1) != uset.end()) {
                continue;
            }

            int cur = num;
            int length = 1;

            while (uset.find(cur + 1) != uset.end()) {
                cur++;
                length++;
            }

            best = max(best, length);
        }

        return best;
    }
};
```

例如 `nums = [100,4,200,1,3,2]`：

- `1` 没有前驱 `0`，是起点，扩展得到 `1,2,3,4`，长度为 4。
- `2、3、4` 都存在前驱，因此跳过，不会重复扫描这条序列。
- `100` 和 `200` 分别是长度为 1 的序列。

## 为什么必须遍历 `uset`

如果第二轮遍历原数组 `nums`，重复的起点会重复扩展同一段序列。例如很多个 `1` 加上 `2,3,4,...` 时，每个 `1` 都会重新扫描整段序列，时间复杂度可能退化到 `O(n²)`。

改为遍历去重后的 `uset` 后，每个不同的数字只处理一次；再配合“没有前驱才扩展”，每段连续序列只会从起点扫描一次。

## 正确性要点

1. 集合去除了重复值，连续序列中的每个数字只保留一份。
2. 若 `num - 1` 存在，`num` 一定不是序列起点，跳过不会漏解。
3. 若 `num - 1` 不存在，从 `num` 开始不断查找后继，可以得到该序列的完整长度。
4. 所有连续序列都恰好有一个起点，因此取所有起点长度的最大值就是答案。

## 复杂度

- 构造集合：平均 `O(n)`。
- 遍历和扩展：平均 `O(n)`；每个不同数字至多参与一次序列扩展。
- 总时间复杂度：平均 `O(n)`。
- 额外空间复杂度：`O(n)`。
- `unordered_set` 的哈希操作理论最坏可能退化，但通常按平均 `O(1)` 分析。

## 本轮复盘

用户最初已经采用了“集合 + 判断序列起点”的正确方向，但第二轮遍历原数组，导致重复数字可能重复扫描并触发超时。改为遍历 `uset` 后通过 LeetCode 提交；`best = 0` 可正确处理空数组，重复元素由集合自动去重。
