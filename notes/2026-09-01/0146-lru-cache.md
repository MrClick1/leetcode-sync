# 146. LRU 缓存 —— 复盘笔记

状态：✅ 已解决（2026-09-02 完成验证）

## 核心设计

LRU 缓存需要同时满足两个要求：

- 通过 key 在平均 O(1) 时间内找到缓存节点。
- 在平均 O(1) 时间内更新节点的使用顺序，并淘汰最久未使用的节点。

因此使用两种数据结构配合：

```cpp
unordered_map<int, DListNode*> umap;
```

哈希表负责通过 key 定位节点；双向链表负责维护使用顺序。`head->next` 是最近使用的节点，`tail->pre` 是最久未使用的节点。头尾虚拟节点让插入和删除不需要单独判断边界。

每个数据节点必须同时保存 key 和 value：

```cpp
struct DListNode {
    int key;
    int val;
    DListNode* next;
    DListNode* pre;
};
```

value 用于回答 `get`，key 用于淘汰节点时同步删除哈希表记录。

## 操作过程

### get

如果 key 不存在，返回 `-1`。如果存在，节点已经位于链表中，所以必须先执行 `removeNode`，再通过 `insertIntoHead` 移到最近使用位置，最后返回节点的 value。

### put：更新已有 key

更新节点的 value，然后将节点从原位置摘下并移动到链表头部。哈希表中保存的节点地址没有变化，不需要重新创建节点。

### put：插入新 key

- 缓存未满：创建节点，同时插入链表头部和哈希表，缓存大小加一。
- 缓存已满：取出 `tail->pre`，从链表和哈希表中同步删除，再将新节点插入链表头部和哈希表。

## 必须保持的同步关系

- 哈希表中的每个 key 都对应链表中的一个有效数据节点。
- 每个数据节点在双向链表中只出现一次。
- 移动已有节点时必须先摘除，再插入头部，否则会破坏链表甚至形成环。
- 淘汰节点时必须同时删除链表连接和哈希表记录。
- 哈希表的 key 是 `put` 的 key，节点的 `val` 是 `put` 的 value，两者不能混淆。

## 调试中遇到的问题

1. 新节点只插入链表，没有执行 `umap[key] = node`，导致随后 `get` 始终返回 `-1`。
2. `get` 命中后直接把节点插入头部，没有先从原位置摘除，破坏了双向链表结构。
3. 淘汰时使用新 key 调用 `erase(find(key))`，对 `end()` 执行 `erase` 产生未定义行为，程序出现无输出退出。
4. 一度使用 `removedNode->val` 作为哈希表 key；当 key 和 value 不相等时，无法删除正确映射。
5. LeetCode 环境预定义了 `ListNode`，自定义同名结构导致重定义；删除自定义结构后又会缺少双向指针和 key。最终改用独立名称 `DListNode`。

## 复杂度

- `get` 平均时间复杂度 O(1)。
- `put` 平均时间复杂度 O(1)。
- 缓存中的有效数据结构占用 O(capacity) 空间。

当前实现没有释放被淘汰的节点，也没有在类销毁时释放剩余节点和虚拟节点，因此实际进程内存可能随插入次数增长。它不影响本题结果，但工程代码中应在淘汰后 `delete` 节点，并补充析构清理。

## 验证

- 固定测试全部通过，覆盖官方示例、容量为 1、更新已有键、`get` 刷新使用顺序、缺失 key 和最大容量。
- 使用 `-Wall -Wextra -pedantic` 编译，无警告。
- 300 组独立随机操作序列验证全部通过，每组包含 1000 次随机 `get` / `put`，并额外检查最终状态。
- 随机测试刻意让 key 和 value 大量不相等，确认淘汰时删除的是正确 key。
