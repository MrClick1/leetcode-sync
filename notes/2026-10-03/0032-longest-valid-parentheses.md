# 32 最长有效括号的动态规划二刷

2026-10-03 用户经过状态、边界与拼接修正后反馈力扣通过。本次记录 DP 解法，重点复习 dp 必须以当前位置结尾，以及 dp[k-1] 已经包含前方能连续拼接的整段有效括号。此前[2026-09-04 的下标栈记录](../2026-09-04/0032-longest-valid-parentheses.md)保留；本题仍只按一题统计。

## 用户通过代码

```cpp
class Solution {
public:
    int longestValidParentheses(string s) {
        int n = (int)s.size();
        int res = 0;

        if (n <= 1) return 0;

        vector<int> dp(n, 0);

        if (s[1] == ')' && s[0] == '(') dp[1] = 2;
        res = max(res, dp[1]);

        for (int i = 2; i < n; ++i) {
            if (s[i] == '(') {
                dp[i] == 0;
            } else {
                if (s[i-1] == '(') {
                    dp[i] = dp[i-2] + 2;
                } else {
                    if (i - dp[i-1] - 1 >= 0 && s[i - dp[i-1] - 1] == '(') {
                        dp[i] = dp[i-1] + 2;

                        if (i - dp[i-1] - 1 > 0) {
                            dp[i] += dp[i - dp[i-1] - 2];
                        }
                    }
                }
            }

            res = max(res, dp[i]);
        }

        return res;
    }
};
```

原样保留用户代码。其中 dp[i]==0 是一次没有使用结果的比较，应改为 dp[i]=0 或省去这一句。当前每个 dp[i] 初始化为零，且只在自己的那轮计算；遇到左括号时零值原本就保留，因此这句无效比较不影响本版算法结果。

## 状态与两种转移

dp[i] 表示必须以 s[i] 结尾的最长连续有效括号子串长度，res 表示所有已处理位置中的最长长度。有效括号必须以右括号结尾，当前字符为左括号时 dp[i]=0。例 ()( 的 dp 为 [0,2,0]，答案取历史最大值 2。

当前为右括号且前一个字符为左括号，形成新的一对 ()，再连接紧邻前方的有效段：dp[i]=dp[i-2]+2。用户单独初始化 dp[1]，循环从 i=2 开始，所以 i-2 始终合法。

当前为右括号且前一个字符也为右括号，先跳过前一位置结尾的有效段 B，其长度为 dp[i-1]。B 的前一个字符下标为 k=i-dp[i-1]-1。若 k>=0 且 s[k]=='('，就能用这对括号把 B 包起来，并连接其前方的有效段 A：

```text
A       ( B )
结束于   k   i
k-1

dp[i] = dp[k-1] + dp[i-1] + 2
```

k=0 时没有 A，前段长度按零处理。只有 k>0 时才能访问 dp[k-1]。可以把重复下标表达式命名为 k，使含义更清楚：

```cpp
int k = i - dp[i - 1] - 1;
if (k >= 0 && s[k] == '(') {
    dp[i] = dp[i - 1] + 2;
    if (k > 0) {
        dp[i] += dp[k - 1];
    }
}
```

这个片段与用户通过版等价，不需要改变原来的 dp[1] 初始化或循环范围。

## 前方有多组括号为何不漏

dp[k-1] 保存以 k-1 结尾的整段最长有效括号，可能包含多组相邻或嵌套的括号，不只是最近的一对。此前的转移已经把能连续连接的部分累积进去。

例如 ()()(())：

```text
下标：0 1 2 3 4 5 6 7
字符：( ) ( ) ( ( ) )
      └─────┘ └─────┘
        A       (B)
```

处理前两组 () 时，dp[1]=2、dp[3]=dp[1]+2=4。处理最后的 i=7 时，中间的 B 是下标 [5,6] 的 ()，dp[6]=2，所以 k=7-2-1=4。前段 dp[k-1]=dp[3]=4，已经包含前面两组 ()。于是 dp[7]=2+2+4=8，一次相加即可全部连接。

前面再多一组 ()，其长度同样会提前累积到 dp[k-1]。如果还能往前连续延长，dp[k-1] 本身作为最长状态就已包含它；不需要在本轮再往前逐组查找。只能接以 k-1 结尾的那一段，不能使用 res 代替它，否则可能越过无法匹配的括号而破坏连续性。

## 本轮错误历史

| 问题 | 原因与修正 |
|---|---|
| 初版访问 dp[-1] | i=1 时 i-2=-1；用户改为单独初始化 dp[1]、循环从 2 开始 |
| 把 dp[i] 与 '(' 比较 | dp 保存长度，应通过 s[i] 判断当前字符；中间版可把以左括号结尾的状态误算为有效 |
| dp[i]==0 | == 比较、= 赋值；最终版此句仍无作用，但零初始化使当前结果正确 |
| ()) 读取 s[-1] | i=2、dp[1]=2，匹配位置 k=-1；先在 && 左侧检查 k>=0 |
| 只返回 dp[n-1] | )()()) 中最后状态为零，前面仍有长度4；改为维护 res |
| 包括号时只加1 | 新匹配一对，应该加2 |
| ()(()) 只得到4 | 只计算末尾 (())，漏接前方 ()；补上 k>0 时的 dp[k-1] |

此前有一版 ()(()) 的结果4来自错误的 dp[3]=4，最终前一版的4则来自末尾 (())。字符判断修复后，不能把这两次同样的输出混为同一个原因。最终版已补前段长度，不继续把历史缺项当作当前错误。

## 复习与验证范围

先定义必须以 i 结尾的 dp，再按当前字符是否为右括号分支。直接组成 () 时接 dp[i-2]；跳过中间段时计算 k、检查匹配、再接 dp[k-1]。最后保留所有位置的历史最大值。

用 ()) 检查 k 的负下标，用 ()( 检查答案不是末项，用 ()()(()) 检查前段已累积多组括号。时间 O(n)，额外空间 O(n)。用户反馈力扣通过，本轮静态审查与手工状态推演正确；没有新增本地编译或运行测试，也没有复用旧栈解法的测试结果来声称 DP 版通过本地测试。
