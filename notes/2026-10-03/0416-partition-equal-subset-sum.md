# 416 分割等和子集

2026-10-03 用户把一维 DP 的目标和遍历改为倒序，并明确反馈力扣通过。核心复习点是每个数组元素只能选择一次：压缩状态后，需要通过遍历顺序保留上一轮的状态。

## 用户通过代码

```cpp
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int n = (int)nums.size();

        int sum = 0;
        for (int i = 0; i < n; ++i) {
            sum += nums[i];
        }

        if (sum % 2 == 1) {
            return false;
        }

        int target = sum / 2;
        vector<bool> dp(target+1, false);
        dp[0] = true;

        for (int i = 0; i < n; ++i) {
            for (int j = target; j >= 1; --j) {
                if (j >= nums[i]) {
                    dp[j] = dp[j] || dp[j - nums[i]];
                }
            }
        }

        return dp[target];
    }
};
```

## 从等和分割转成子集目标和

若两部分的和相同，每部分的和只能是总和的一半。总和为奇数时立即返回 false；总和为偶数时，继续判断能否选择一些元素凑出 target=sum/2。找到这样一个子集后，剩余元素的和也是 target，因此不需要分别搜索两部分。总和为偶数只是必要条件，例如 [1,2,5] 的总和为 8，仍然不能凑出 4。

每个数组元素最多使用一次。即使数组中有相同数值，它们也属于不同下标的元素，可以各选一次；不能把某个下标对应的元素反复选取。

## 状态 初始化与递推

每轮处理完一个元素后，dp[j] 表示只使用已经处理过的元素，能否选择一个子集凑出和 j。初始没有处理任何元素，只有空选择能凑出零，所以 dp[0]=true，其他状态为 false。

处理当前元素 x=nums[i]，对于目标和 j 有两种选择：

| 选择 | 必须满足的上一轮状态 |
|---|---|
| 不选 x | 上一轮已经能凑出 j |
| 选一次 x | j>=x，且上一轮已经能凑出 j-x |

因此更新为：

```cpp
dp[j] = dp[j] || dp[j - x];
```

`||` 表示任意一种选择可行即可。j<x 时不能选择当前元素，保留原来的 dp[j]。这里的关键是两个输入状态都应来自处理 x 之前，而不是本轮使用过 x 后的结果。

## 正序为何错误 倒序为何正确

首版金额 j 从 1 增加到 target。对于 [1,2,5]，target=4，仅处理第一个元素 1 就发生：

| j | 读取的来源 | 首版的结果 |
|---:|---|---|
| 1 | dp[0]=true | dp[1]=true，使用一次 1 |
| 2 | 本轮刚更新的 dp[1]=true | dp[2]=true，相当于再次使用同一个 1 |
| 3 | 本轮刚更新的 dp[2]=true | dp[3]=true，相当于使用三个 1 |
| 4 | 本轮刚更新的 dp[3]=true | dp[4]=true，相当于使用四个 1 |

错误不在递推表达式，而在来源状态被本轮更新过。改成倒序后，本题 x 为正整数，j-x<j；当前从大到小处理 j，较小的 j-x 尚未在本轮更新，仍保存上一轮结果。于是选择当前 x 时，它恰好使用一次。

正确代码在这个反例中的状态：

| 已处理元素 | dp[0] | dp[1] | dp[2] | dp[3] | dp[4] |
|---|---|---|---|---|---|
| 无 | true | false | false | false | false |
| 1 | true | true | false | false | false |
| 1、2 | true | true | true | true | false |
| 1、2、5 | true | true | true | true | false |

5 大于 target，本轮没有可更新的位置；最后返回 dp[4]=false。另 [1,5,11,5] 可以选择 11，其余元素 1+5+5 也为 11；相同值的两个 5 是两件不同元素。

这与 152 滚动变量的旧状态问题有关：152 用临时变量保留上一轮，416 用倒序保证所需的较小状态尚未被覆盖。

## 可选的循环简化

用户从 target 倒序到 1，再用 if 检查 j>=nums[i]，逻辑正确。可把这个检查移进循环条件，少遍历无法选当前元素的位置：

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = target; j >= nums[i]; --j) {
        dp[j] = dp[j] || dp[j - nums[i]];
    }
}
```

两种写法等价，不必为简洁而否定用户已经通过的版本。

## 与零钱兑换的遍历区别

在“外层枚举元素或面额、内层原地更新目标和”的一维写法中：

| 使用限制 | 目标和方向 | 状态来源 |
|---|---|---|
| 每个元素最多一次，如本题的 0/1 背包 | 倒序 | 较小位置还保存上一轮结果 |
| 当前面额可无限重复，如完全背包 | 正序 | 可以利用本轮已经选择该面额的结果 |

不要把这张表套用到所有 DP 循环。此前 322 用户通过版是外层金额、内层硬币；它枚举最后一枚硬币，属于另一种组织方式。本题要逐个限制数组下标的使用次数，不能把循环方向机械照搬过来。

## 复习与验证范围

重写时先说“找和为总和一半的子集”，再写 dp[j] 的含义和 dp[0]。写转移前问自己“当前元素允许重复使用吗”；若只允许一次，确认 dp[j-x] 仍来自上一轮。用 [1,2,5] 手算第一轮，应只有 dp[1] 新变为 true。

令 T=sum/2，求和 O(n)，DP 时间 O(nT)，额外空间 O(T)。用户反馈力扣通过，本轮静态审查和手工状态推演正确；没有新增本地编译或运行测试。
