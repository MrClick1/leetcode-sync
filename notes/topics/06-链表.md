# 链表

## 共性框架

链表题的核心是节点连接关系，不是节点值。写指针修改前，先明确：

```text
当前区间的前驱是谁？
修改后新的头和尾是谁？
剩余链表从哪里开始？
是否保存了即将丢失的 next？
```

虚拟头节点可以统一处理“原头节点也会改变”的情况。

## 23. 合并 K 个升序链表

- 最小堆中只保存每条非空链表当前最小的节点。
- 每次弹出最小节点接到答案尾部。
- 如果弹出的节点存在 `next`，把后继加入堆。
- 堆中最多保存 `k` 个节点，因此每个节点的堆操作为 `O(log k)`。

交叉专题：[堆与数据流](10-堆与数据流.md)。

## 24. 两两交换链表节点

设 `prev` 指向当前一对节点之前：

```text
prev → first → second → nextPair
```

交换后：

```text
prev → second → first → nextPair
```

完成三次连接后，原来的 `first` 成为这一对的尾部，下一轮让 `prev = first`。

## 25. K 个一组翻转链表

每轮先从 `groupPrev` 向后确认是否存在完整的 K 个节点：

- `groupStart = groupPrev->next`
- `groupNext = kth->next`
- 只反转区间 `[groupStart, groupNext)`
- 让反转时的 `prev` 初始为 `groupNext`，组尾会自然连接下一段
- 原 `groupStart` 反转后成为组尾，也是下一轮的 `groupPrev`

早期思考记录见 [2026-08-30 版本](../2026-08-30/0025-reverse-nodes-in-k-group.md)，最终完成版以上面的 2026-09-01 笔记为准。

## 146. LRU 缓存

两个结构各司其职：

- 哈希表：`key → 节点地址`，负责平均 `O(1)` 查找。
- 双向链表：头部表示最近使用，尾部表示最久未使用，负责 `O(1)` 摘除和插入。

访问或更新已有 key 时，把节点移动到链表头；容量满时删除尾部节点，并同步删除哈希表记录。

## 指针安全检查

- 修改 `next` 前是否保存了原后继？
- 新头是否正确接回前驱？
- 新尾是否正确接回剩余链表？
- 循环指针是否推进，是否可能形成自环？
- 虚拟头节点是否放在栈上，或是否需要释放堆内存？
