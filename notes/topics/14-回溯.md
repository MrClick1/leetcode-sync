# 回溯

## 共性框架

回溯用于枚举满足约束的候选方案。先选一个候选，继续填剩余位置；这个选择下面的情况探索结束后，恢复选择之前的状态，才能干净地尝试另一个候选。

先问三个问题：当前方案记录在哪里？这一层可以选择什么？什么时候得到完整答案？再为本次选择的每项修改写出对应的撤销操作。

把搜索过程看成选择树：节点记录一个尚未完成的方案，边代表本次新选择。一个调用中的循环尝试同一位置的不同候选；递归调用继续填下一位置。完整方案可在叶子收集，但并非所有回溯题都只收集叶子，子集类题目还会收集中间节点。

递归是一种函数调用方式，回溯是搜索时恢复状态的策略。不能把二者简单等同：归并排序使用递归，却不会在合并之后撤销排序结果。递归返回也不会自动撤销对共享 path 或 used 的修改。

## 三个设计步骤

1. 定义一次搜索的任务和参数。例如 46 中，一次调用负责在当前 path 后继续补齐排列，nums 提供候选，used 标记当前排列已经使用的元素。
2. 定义收集与停止条件。例如 path 长度等于 nums 长度时，复制保存本方案，然后返回当前调用。
3. 定义同层候选循环：跳过不合法候选，选择候选，递归探索，再撤销本次选择。枚举全部答案时，通常不能在找到第一个答案后从所有祖先调用提前返回。

## path、used 与 result

- path：正在构造的单个方案，随选择与撤销变化。
- used[i]：nums[i] 是否已在当前方案中。不是在整棵搜索树中永远不可再次使用。
- result：保存已经完成的独立方案。把 vector<int> path 放入 vector<vector<int>> result 时会复制，之后修改 path 不会修改已存的结果。

## 46 的第一个回溯过程

对 nums=[1,2,3]，先选择 1，再选择 2，再选择 3，得到完整路径 [1,2,3]。收集并返回后，父调用撤销它选择的 3，路径恢复 [1,2]。这一层已无其他可选数字，继续返回；上一层撤销它选择的 2，路径恢复 [1]，再改选 3，下一位置就可以选择 2，得到 [1,3,2]。

每层只撤销自己添加的选择。return 负责回到调用处，pop_back 和解除 used 标记负责恢复共享状态；两者不能混为一谈。

每次调用中的局部循环变量 i 独立，而成员 path/result 与按引用传入的 used 共享。内层返回后，外层继续在自己的递归调用语句之后执行；循环走完也会自然返回。一个调用要探索其入口前缀下的全部补齐方式，例如前缀 [1] 对 [1,2,3] 要找到 [1,2,3] 和 [1,3,2]，不能找到第一个结果就结束全部搜索。

排列考虑顺序，选择 2 后仍需允许选择下标较小的 1，因此每层重新遍历所有下标，用 used 跳过本路径已选元素，而不是只递归到 i+1 之后的下标。组合与排列的搜索范围不要照搬。

用户原版先 used[i]=false 再 path.pop_back，同样正确。完整搜索后 path 自动回到空，但成员 result 不会自动清空；复用同一个对象调用入口时，应初始化 path/result，而不是在每个递归调用中清空。

### 46 的交换式回溯

用户随后学习官方交换式实现：数组前 first 个位置作为已选前缀，后缀保存所有未选候选；遍历后缀，将候选交换至 first，递归 first+1，再交换相同位置恢复。无需 used，但仍有 O(n) 递归栈，不计输出不能说是 O(1) 空间。

循环从 first 开始不会漏掉原来下标较小的数字，因为数组位置在动态变化，例如选择 2 后 [2 | 1,3] 仍可以选择候选 1。每层只撤销本层交换，下层返回前已撤销它的所有交换；保存答案会复制数组。模拟与映射见日期笔记的“官方交换式回溯”，不将参考官方代码等同于已独立掌握或提交通过。

## 78. 子集：每个节点都是答案

用户独立给出的 path + startIndex 实现已通过并复核。子集不要求使用全部元素，每个当前 path 都合法，因此进入递归就收集，包括入口的空集。选择 nums[i] 后，只从 i+1 继续，原始下标严格递增；对互异数组，同一子集只有一种生成顺序，无需 used，也无需排序。

当 startIndex==n，先保存当前 path，然后 for 没有候选，函数自然返回，不必添加显式终止判断。若在收集之前直接 return，会漏掉相应答案。入口 res.clear/path.clear 正确避免重复调用累积结果。

复习对照：排列考虑顺序、完整长度才保存、每层从头选未使用元素；本题子集不考虑顺序、每层都保存、只选当前元素之后的候选。都需要递归后撤销本层选择。2^n 个子集保存全部元素共需 O(n×2^n) 时间，不计输出辅助空间 O(n)。

## 17. 电话号码的字母组合：每层固定一个数字位置

每个数字必须贡献一个字母，并且最终字母的位置与数字的位置对应。不是“从数字中挑几个”，而是“从每个数字的字母组中各挑一个”。例如 23 是从 abc 和 def 两组各选一个字母。

定义一次调用：path 已经填好 digits 前 index 个位置，现在负责填第 index 个位置。取当前数字的字母组，只循环这个组的字母，选择一个字母，递归 index+1，然后删除本层添加的字符。index==digits.size 时复制保存并 return；不是像子集一样保存每个中间 path。

用户原版沿用子集的外层 startIndex 循环，也能正确得到全部答案：跳过数字的分支无法达到所需长度，因此不会被保存。不过这些分支是不必要的，删去数字位置循环更符合本题定义。原版完整路径时 startIndex 已到末尾，所以缺少显式 return 在该原版中不导致错误；整理版直接访问 digits[index]，应先终止并返回。

后续用户仅把保存条件换成 startIndex==n，却保留外层循环：23 会误保存 d/e/f。到达数字末尾不等于处理了全部数字，因为外层循环允许跳过数字。只有固定每层处理 digits[index]、每次添加一字母并递归 index+1，维持 index==path.size()，才能用 index==n 代表完整答案。具体复现见日期笔记后续疑问。

不需要 used：递归层数已确保一个数字位置只处理一次，不同数字允许选相同字母，如 22 的 aa。区别不是是否允许字母重复，而是每个数字位置都必须参与。

已通过侧边栏读取 [代码随想录 17 讲解](https://programmercarl.com/algo/backtracking/0017-letter-combinations-of-a-phone-number.html)，核对它使用数字位置 index 与当前字母组循环的核心结构。用户 unordered_map 映射也可用，不必为了正确性改成文章的固定字符串表。

复习口诀：位置决定层数，字母决定分支；每个数字选一个，选完再收集；选一个、深入、撤销一个。字符操作见 [C++ string 语法](../01-cpp语法知识文档.md)。

用户随后确认固定数字位置新版通过，完整代码与新旧对照已补到日期笔记。新版只构造前缀，旧版还枚举跳过数字的部分方案；23 的调用为 13 对 16 次，9999 为 341 对 625 次，但完整结果相同。当前字母循环 i 与数字位置 index 不同：所有本层字母候选都递归 index+1，不能改成 i+1。本轮三份 C++ 实现重新校验全部 4680 个合法输入通过，新版每次入口 index==path.size 的断言成立；参考实现与用户代码的 char/int、复制/引用等语法差异均非正确性问题。

## 39. 组合总和：组合允许重复选择，不需要枚举顺序

用户初版尝试每层从 0 枚举，再把 path 放进集合去重。C++17 默认 std::hash<vector<int>> 不可用导致编译失败；仅改用 set 能编译，但查询未排序的 path、插入排序后的 temp，会放过同一组合的其他排列。仅替换容器的诊断中，[2,3,6,7]、target=7 生成 4 个结果，实际只有 [2,2,3] 和 [7] 两种组合。

更合适的方向是在搜索时规定候选原始下标不下降：for 从 startIndex 开始，选择 i 后递归传 i，允许继续使用当前候选；与 78 递归 i+1、只使用一次不同。这不要求排序，但排序能额外支持按值提前剪枝。正整数前提使 sum 超过 target 后无需继续。

初版仅做编译及错误复现；历史代码、集合语法替代和状态清空问题见日期笔记，最终通过版已保存在同一笔记末尾。

后续用户采用 startIndex，却在声明顺序 sum/startIndex 下递归传 startIndex/sum+num：[2]、target=2 的下一层变成 sum=0、起点=2，提前返回，结果为空。只修参数顺序、仍传旧 startIndex 又会产生 [2,3] 与 [3,2]；所需调用是 sum+num, i, target。记忆重点不是照抄参数名，而是按位置核对本次选择之后的状态含义。中间 6 个固定诊断验证修改方向后，用户已修正并确认力扣通过。

最终原版经 12 个固定、1008 个穷举、500 个随机输入，共 1520 个 C++17 校验，与独立候选次数枚举一致；输入不变、同对象复用、path 恢复、无重复及原始下标非递减等检查通过。用户仍觉模糊，不标记为熟练掌握。

已直接读取 [代码随想录指定页面](https://programmercarl.com/algo/backtracking/0039-combination-sum.html)，基础结构与用户相同。一次调用继续补齐已有 path：for 同层换候选，递归下层继续选，返回后撤销本层选择。用户传 sum+num，未改本层 sum，所以只需撤销共享 path；文章先 sum+=num，再递归，需要将本层 sum 减回去。参数排列不同不是错误，各自声明与调用一致即可。

## 22. 括号生成：状态分类与两种动作

用户首版 left/right 表示已使用的左右括号数量。先排除 right>left，后面却用 left<right 执行扩展，该分支不可达；n=1 先放 '(' 后进入 left=1/right=0，两个选择分支都不成立，自然返回，答案为空。

一种整理方式是分别判断 left<n 和 right<left，前者保证左括号不超额，后者保证当前有左括号可闭合。两者可以同时成立，需分别探索；每条分支返回后恢复本层状态，不能把这两个动作条件简单写成互斥 else if。仅反转原来的比较还缺 left 上限，可能无限添加左括号。

用户最终保留 if/else if 也正确：入口先排除 left>n 或 right>left；left==right 时只放 '('，left>right 时在同一分支内分别探索 '(' 与 ')'。分类的是互斥状态，仍覆盖所有合法动作。left==n 时多试一个 '(' 会在下一次入口立即剪枝；选择前检查 left<n 可减少无效调用，但不是通过所需修正。

本题不需要 startIndex：本层候选是两种括号动作，计数决定合法性。通过剪枝后满足 0<=right<=left<=n，right==n 已能推出两类括号都用完。每层 ++/-- 恢复局部计数，push_back/pop_back 恢复共享 path，配对正确。用户最终版已力扣通过；本轮 C++17 对全部 n=1..8 与独立位掩码穷举参考一致，共 2055 个合法结果，复用对象、path 恢复及无重复检查通过，详见日期笔记。

后续局部 res/path + 引用参数版同样正确，入口每次构造空对象，不再需要 clear；引用共享路径仍需 pop_back。与用户贴出的官解对照：官解用 open<n/close<open 两个动作条件在选择前检查，避免先超额后剪枝；传 open+1/close+1 不改变本层整数，所以不用减回去；合法计数约束保证长度 2n 时各有 n 个括号，与用户 right==n 收集等价。新用户版与官解对全部 n=1..8 各与穷举参考一致，不将本地复核称作用户再次力扣提交。

## 79. 单词搜索：进度下标替代字符串路径

首版起点未加入路径、递归行列传反、错误前缀不剪枝，已保留历史反例。用户修正版确认力扣通过，起点与邻居均成对选择/撤销，逐字符检查邻居且坐标正确；尚可先筛掉错误首字母，减少无用搜索。

所给官解一次 check(i,j,k) 从当前格匹配 word[k...]，检查当前字符，不构造 path。匹配最后一个字符直接 true，此时本层还未标记访问；未完成则标记当前格、尝试四邻 k+1、统一撤销返回。外层只枚举起点，有成功直接返回。当前匹配后，k 对应用户 path.size()-1，而用户邻居检查的 path.size() 对应下一层 k+1。

助手整理版统一入口边界/访问/字符检查，保留成员方向表与 const 引用，加入 word 长于格子数直接 false。k 按值传递，本层不变；visited 共享，仍需撤销。用户版、官解、助手版各对 13 固定+2940 穷举+200 随机，共 3153 个输入与独立 BFS 简单路径参考一致，输入不变、状态恢复及对象复用通过。用户仍觉得繁杂，建议先口述“当前格匹配第 k 个字符”再独立重写，不标记熟练掌握。

用户随后独立改写 k 版，入口匹配当前字符，但仍由调用者先标记邻居/起点，递归返回后撤销，再判断成功返回。这种分工也正确，不必强制改成官解；本层当前格由父调用撤销，所以不能直接在入口用 visited[r][c] 拒绝当前格。已同样对 3153 个输入验证，并直接检查父调用标记保留、后代标记恢复，尚待新版本力扣提交反馈。可去掉成功条件中的重复字符比较，末尾 return flag 简化为 return false。

## 131. 分割回文串：固定起点，枚举终点

用户首版 substr 误传迭代器，第二版改为下标/长度后，回文检查仍因忘记 ++l/--r 在首尾相同时死循环。最终补上双指针推进，用户明确反馈力扣通过；C++17 对 14 固定+510 穷举+200 随机，共 724 个输入与独立切割位掩码参考一致，路径恢复、完整覆盖和无重复等检查通过。

一次调用在已有 path 后继续分割 s[startIndex..]。本层 startIndex 固定，i 枚举当前段的终点；取 substr(startIndex,i-startIndex+1)，只选择回文段，递归 i+1，再撤销本段。进度只向右，不需要 used；startIndex 到末尾保存整组方案。用户收集后没写 return 也正确，此时循环无候选、自然结束，可加 return 提高清晰性。先熟悉这个基础分割框架，不主动换预处理实现。
